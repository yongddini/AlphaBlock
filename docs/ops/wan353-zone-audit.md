# 존 대장 감사 — 서버 1회 실행 런북 (WAN-353 = WAN-343 §5 서버 몫)

> ✅ **08-17·08-18 판정은 났다(서버 실행 2026-08-22): `무효화 선행` 23/28(82.1%) = 라이브가
> 무효화를 「한 봉 늦게」 아는 **알려진 근사**. 엔진 파리티 결함 아님 · 수정 이슈 없음.**
> 정본은 **CLAUDE.md의 WAN-353 문단**이다(사유별 표 · 클러스터 경고 · 설명 안 되는 5건 ·
> 읽는 순서까지). 이 런북은 이제 **다른 날짜에 같은 자를 다시 댈 때**의 절차서다.
>
> 📌 **그래도 이 문서는 판정을 담지 않는다.** 아래 §3(읽는 법)은 실행 **전에** 정해져 있어야
> 한다 — 실행하고 나서 정하면 결과에 맞춰 자를 고르게 된다(wan343.md §5가 미리 못 박아 둔
> 이유). 새 날짜를 돌릴 때도 §3을 **먼저** 읽고 시작한다.

## 0. 무엇을 묻나

WAN-342가 짝 없는 셋업을 조인 키 조각으로 갈랐고 **`(a) 존 없음`이 두 날 모두 13/17
(76.5%)** 였다. WAN-343이 그 `(a)`가 **관찰이지 원인이 아니라는 것**을 밝히고, 백테 **존
아카이브**를 직접 보는 자(`--zone-audit`)를 실었다. 남은 것은 그 자를 **한 번 대는 일**이다.

갈래와 후속이 사유마다 **완전히 다르다** — 가르지 않으면 알려진 근사를 결함으로, 결함을
근사로 읽는다:

| 갈래 | 뜻 | 후속 |
| -- | -- | -- |
| `창 밖` | 백테 탐지 창(워밍업)보다 이른 존 | 대조 도구의 근사 → `--warmup-days` |
| `존 미탐지` | 창 안인데 백테가 그 존을 만든 적이 없다 | **엔진 파리티 결함** → 별도 이슈 |
| `확정 시각` | 존 시작은 같은데 확정 봉이 다르다 | **엔진 파리티 결함** → 별도 이슈 |
| `무효화 선행` | 백테가 라이브 탭 전에 그 존을 죽였다 | **문서화된 근사** → CLAUDE.md 문단 |
| `소멸 선행` | 백테에서 이미 소멸(swept)했다 | 무효화 축과 같은 갈래 |
| `탭 기록 없음` | 존은 양쪽에 있는데 그 봉의 탭이 백테에 없다 | 탭 판정 축 |
| `설명 안 됨` | 존도 탭도 있는데 셋업 행이 없다 | 이 감사가 못 가르는 자리 |
| `대상 아님` | 존 정체성 없음 · 백테 쪽 행 · 대장 미제공 | 분모에서 빠진다 |

**후보 둘은 이미 기각됐다** — ① 라이브 운영 이벤트(러너 재시작): 시각 클러스터 3개 중
**1개만** 겹침(wan343.md §1) · ② 탐지 컨텍스트 창: 공통구간 존 666개 중 불일치 **6개
(0.90%)**, 생애 필드 불일치 **0건**(§2). 남은 유력 후보는 **무효화 시점**이다 —
`live.limit_engine.on_htf_bars`가 「한 봉 늦는 알려진 근사」라고 이미 자백해 뒀다.
⚠️ **가설이지 판정이 아니다.**

## 1. 왜 그냥 두 줄을 치면 안 되나 — 순서

```bash
# 🚨 이렇게 치지 말 것 (이슈 본문의 옛 예시)
uv run alphablock stop-width --day 2026-08-17 --with-backtest --zone-audit --jobs 4
```

둘이 틀렸다:

1. **되채우기가 먼저다.** `stop-width --with-backtest`는 **옛 엔진 판을 기본 거부**한다
   (WAN-335 규약 — 파리티 측정이라 엔진이 다른 두 판을 빼면 「집행 차이」가 아니라 「엔진이
   바뀐 몫」이 섞인다). 그런데 서버의 마지막 되채우기(WAN-338, 08-20) 뒤 **캐시 지문을 이루는
   엔진 파일이 바뀌었다**(WAN-336/345/346이 얹은 옵트인 관측·배선). 캐시 **버전**(`wan339.1`)은
   그대로이고 **엔진 지문**이 움직였으므로 그 두 날은 지금 엔진 기준으로 **전 칸 미스**일 수
   있다. 미스여도 감사는 **틀리지 않는다** — `stop-width`가 그 칸을 직접 계산한다. 다만 그
   계산이 캐시에 안 남아 **다음 실행이 또 처음부터 돈다**. WAN-334를 네 번 포기하게 만든
   자리다.
2. **`--jobs`를 손으로 넘기면 서버가 일부러 정한 값을 덮어쓴다.** 서버는 **2코어 1GB**이고
   워커마다 1분봉 사본이 들어가서(WAN-324/354) WAN-356이 `.env`의 `ALPHABLOCK_BACKTEST_JOBS`를
   그 박스에 맞춰 넣어 뒀다. 그런데 `config/settings.py` 규약상 **명시적 `--jobs N`이
   환경변수를 이긴다** — 그래서 스크립트는 기본으로 `--jobs`를 **아예 안 넘긴다**. 러너와
   코어를 다투는 게 걱정될 때만 `-j 1`처럼 명시한다. 📌 `--jobs`는 결과를 안 바꾸는 순수
   성능 노브라(WAN-121: 직렬 = 병렬 비트 동일) **판정은 어느 쪽이든 하나도 안 움직인다.**

## 2. 돌리는 법 — 한 줄

```bash
cd ~/AlphaBlock
git pull                       # PR #285(--zone-audit)와 이 런북이 있어야 한다
tmux new -s wan353             # 되채우기가 길다 — 세션 끊김에 대비
./scripts/wan353-server-zone-audit.sh -o wan353-report.md
```

스크립트가 순서대로 한다: **엔진 지문 → 두 날 엄격 조회(`--no-stale`) → 미스인 날만
되채우기 → 감사 두 번 → `data_gap_skips` → 붙여넣을 요약.** 종료 코드와 소요 시간을 단계마다
적으므로 **어디서 죽었는지가 보인다**(「실패가 성공과 같은 모양」 방지, WAN-194/318/321).

| 옵션 | 뜻 |
| -- | -- |
| `-o FILE` | 리포트를 파일로(권장 — 이슈에 붙여넣기용) |
| `-j N` | 워커 수. **미지정이 기본**이고 그때는 서버 `.env`의 `ALPHABLOCK_BACKTEST_JOBS`가 이긴다. 러너와 다투면 `-j 1`로 **덮어쓴다** |
| `-n` | 되채우기 건너뛰기(이미 했다면). ⚠️ 감사는 여전히 옳지만 다음 실행이 또 처음부터 돈다 |
| `DAYS="..."` | 판정 날짜 덮어쓰기(기본 `2026-08-17 2026-08-18`) |

🚨 **쓰는 단계는 되채우기 하나뿐이고, 그건 야간 크론과 같은 경로다**
(`alphablock trades --persist-cache` → `timeline_cache_*` 적재). 삭제·정리(`--prune-*`)는
하지 않는다(WAN-194/297 원칙). 나머지 단계는 전부 읽기 전용이고, 엔진·전략·기본값·토대를
건드리지 않는다.

⚠️ 하루치 48셀이 서버 실측 **6분 23초**였다(WAN-322/324). 2코어에서는 더 걸릴 수 있다.

## 3. 읽는 법 — 실행 전에 못 박아 둔 규칙 (wan343.md §5)

도구가 마지막에 **「판정:」 한 줄**을 스스로 찍는다. 그게 완료기준 2의 답이다.

* **`무효화 선행` 과반** → §0 표의 **문서화된 근사**다. **크기를 기록하고 CLAUDE.md 문단으로
  닫는다**(수정 이슈 아님). 📌 리포트가 함께 찍는 **「무효화 봉 = 라이브 탭 봉」 건수**를
  같이 옮길 것 — 그게 `on_htf_bars`의 **「한 봉」 서명**이다.
* **`존 미탐지`(또는 `확정 시각`) 과반** → 창으로 설명되지 않는 **엔진 파리티 결함**이다.
  별도 이슈로 뺀다(§2가 창 가설을 이미 기각했으므로 이 경우 원인은 창이 **아니다**).
* **`창 밖` 과반** → 대조 도구의 워밍업 근사다. `--warmup-days`를 늘려 재확인한다.
* **과반이 없으면 한 사유로 닫지 않는다** — 사유마다 따로 본다(WAN-161 규약). 도구가
  「과반 사유 없음」으로 그렇게 찍는다.

⚠️ **`대상 아님`은 분모에서 빠진다** — 백테 쪽 짝 없는 행은 같은 자로 잴 수 없다. 러너가
존 대장을 영속화하지 않기 때문이고(재파생 가능한 값이라 스냅샷에서 뺐다, WAN-306) 지어내지
않는다.

⚠️ **탭 시각 기준은 상한이다** — `focus_ms`(체결 → 예약 → 존확정)라 감사는 상위TF **봉
단위**로만 판정하고 초 단위 비교를 하지 않는다.

## 4. 두 조각 — 하나는 닫혔고 하나는 남았다

* ✅ **완료기준 4 — 08-18 `10:04` 1건: 「설명 안 됨」이다.** WAN-343 §1이 재시작 가설을
  기각하면서 **딱 하나** 겹친 클러스터로 남긴 시각인데, **무효화 선행으로도 설명되지 않는다**
  (BTC 15m · 존 생존 · 그 봉 탭 기록 있음). 즉 재시작 계정도 이 근사도 아니고, 설명 안 되는
  5건 중 하나로 CLAUDE.md 문단에 **되살릴 조건과 함께** 남겼다. 새 날짜를 돌릴 때 리포트 §4가
  같은 방식으로 특정 시각 행을 뽑아 준다(`LONE_CLUSTER_*`).
* ⏳ **완료기준 5 — `data_gap_skips`(WAN-314 §3): 아직 한 번도 대조한 적이 없다.**
  ⚠️ **현재 상태 스냅샷**이라 판정 두 날 당시 기록이 이미 덮였을 수 있다 — 없으면
  「**확인 불가**」로 적는다(지어내지 않는다, WAN-194). 리포트 §5가 그 문구를 스스로 찍는다.
  📌 이 대조가 없어도 **WAN-343 §1의 러너 재시작 기각은 이미 섰다**(시각 클러스터 3개 중 1개만
  겹침) — 두 개를 섞지 말 것.

## 5. 읽지 말아야 할 것

* 🚨 **크기(08-17 23.3% · 08-18 37.8%)를 「파리티 대조가 그만큼 틀렸다」로 읽지 말 것** —
  짝 없는 셋업은 손절폭 표에서 **빠지고**(WAN-333) 편향 점검 Δ가 0.000%p·−0.014%p로 작다.
  **WAN-334의 손절폭 판정은 안 뒤집힌다.** 이 값이 재는 것은 「대조가 못 보는 셋업의 비중」이다.
* ❌ **손절폭 가드(0.3%)·존폭 필터(1.28) 값을 이 실행으로 바꾸지 않는다** — WAN-76/79 ·
  WAN-159 소관 · 재-베이스라인 = 사용자 결정.
* ❌ **러너 창(`live_signal_lookback_bars`)·백테 워밍업(`DEFAULT_WARMUP_DAYS`) 기본값을 바꾸지
  않는다** — WAN-343 §2가 「그 구간에서는 탐지가 같다」를 보였으므로 바꿀 근거가 없다(바꾸면
  옛 대조 표가 통째로 무효가 된다). `--warmup-days`는 **재확인용 노브**이지 기본값 변경이 아니다.
* ❌ **봉 재수집·데이터 수정**(WAN-327/329 계열) — 판정 사흘의 15m 손상 **0봉**으로 이미 배제됐다.
* ⚠️ 백테 수익률은 기대수익이 아니다 — `baseline`(낙관) 렌즈 위 값 ·
  **「엣지 없음」(WAN-84/88/111/114/124/151/201) 불변** · `ALPHABLOCK_LIVE_TRADING=false` 유지.
