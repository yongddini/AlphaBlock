# 팔 종목 목록 켜기 — WAN-451 ③ 단계(종목 풀 · 매주 목록)

스토캐스틱 팔이 매매할 종목을 **매주 월요일 00:00 UTC(KST 09:00)** 에 정하고, 그 종목들의 봉을
모으는 부분이다. 이것만 켜서는 **매매가 하나도 안 바뀐다** — 수집기가 더 많이 모을 뿐이다.
팔(`ALPHABLOCK_LIVE_ARM_ENABLED`)을 켜면 러너가 이 목록으로 감시 종목을 바꾸고 목록 밖 진입을 막는다
(팔은 이 스위치가 켜져 있어야 기동한다).

## 무엇을 하나

| 할 일 | 언제 | 무엇을 |
| -- | -- | -- |
| 후보 풀 일봉 수집 | 기동 직후 1번 · 매일 00:00 UTC + 2분 | 지금 상장된 USDT 무기한 **전체**(약 520종목)의 **1d만** REST로 |
| 이번 주 목록 계산 | 같은 때 · 이번 주 목록이 아직 없을 때만 | 직전 30일 평균 거래대금(`거래량 × 종가`) 상위 31종목 · 자격: 상장 90일 이상 · 마지막 일봉 3일 안 |
| 알림 | 새 주 목록을 저장할 때 1번 | 들어온 종목 · 빠진 종목(텔레그램 · 평문) |
| **팔 종목 수집** | 기동 직후 · 목록이나 보유 종목이 바뀌면(1분마다 확인) | 그 주 31종목 + 목록에서 빠졌지만 포지션을 들고 있는 종목 × 1m·15m·1h·4h·6h·8h·12h·1d·1w(웹소켓) · 3h는 1h에서 만들어 저장 · 2h는 저장소가 1h에서 파생 |

- 규칙은 백테스트 정본과 **같은 함수**다(`data/universe.py`). 다른 것은 **후보 풀 하나**다.
  정본은 「2020-09-15 이전 상장 53종목 고정」이었고, 페이퍼는 「지금 상장된 전체」다
  (사용자 결정 ② 나, 2026-10-14). 이 풀로 돌린 백테스트는 없다.
- **한 번 저장한 주는 덮지 않는다.** 나중에 데이터가 바뀌어도 그 주에 실제로 고른 목록이 기록이다.
- 그 주 일요일 봉이 없는 종목이 풀의 10%를 넘으면(수집 실패) 저장하지 않고 **30분 뒤 다시** 한다.
  늦게 계산해도 월요일 00:00까지 닫힌 일봉만 읽으므로 결과는 같다.
- 빠진 종목의 보유 포지션은 유지하고 **새 진입만 막는다**(정본 `force_close=False`). 수집은 포지션이
  남아 있는 동안 계속한다.
- **러너(팔 켰을 때)**: 매 폴링 감시 시리즈를 「그 주 목록 × 팔 TF 10개 + 포지션·대기 주문이 남은 칸」으로
  맞춘다(31종목이면 310개). 빠진 칸은 엔진 상태·스냅샷을 지운다. 체결 순간 그 종목이 그 주 목록에 없으면
  `arm_rotation`, 그 주 목록이 아직 저장 전이면(월요일 00:00 UTC 직후 몇 분) `arm_rotation_unknown`으로
  **진입을 거부**하고 장부에 남긴다(지난주 목록으로 대신 판정하지 않는다). 틱 피드도 감시 종목을 따라
  다시 만든다.
- **3h는 1h에서 접는다.** 백테스트 정본은 1분봉에서 접었는데, 로컬 DB 31종목 54.9만 봉에서
  두 방법의 시가·고가·저가·종가·거래량이 **전부 같았다**(불일치 0).
- 목록이 바뀌면 새 종목의 과거를 먼저 채운 뒤(종목당 TF 9개 · 약 8초) 웹소켓을 다시 붙는다.
  이것은 오류가 아니라서 「수집기 스트림 복구」 알림이 울리지 않는다.
- 웹소켓은 연결 하나에 스트림 200개까지 싣는다. 팔 종목이 붙으면 300개 안팎이라 **연결 2개**다.
  한 연결이 끊기면 나머지도 함께 끊고 전부 다시 붙는다(반쪽만 살아 있는 상태를 남기지 않는다).

## 켜기 (서버 · 사용자 수행)

```bash
cd ~/AlphaBlock && echo 'ALPHABLOCK_UNIVERSE_ENABLED=true' >> .env
```

```bash
sudo systemctl restart alphablock-collector
```

첫 적재는 풀 전체의 일봉 5년치다. 로컬 맥 실측(2026-10-15)은 **520종목 · 44.4만 행 · 342초 · 실패 0 ·
DB +50MB**였다. 다음 날부터는 새로 닫힌 일봉 하나씩이라 몇 분이면 끝난다. 스트림은 그 전에 붙는다(백그라운드).
요청 사이에 0.5초 간격을 둬서 바이낸스 요청 한도(분당 가중치 2400)를 넘지 않는다.

팔 종목 수집이 붙으면 기동 때 31종목 × TF 9개의 과거를 더 받는다. 로컬 맥 실측(2026-10-15)은
**279쌍 · 62만 봉 · 4분 40초 · 실패 0 · DB 약 +70MB**였고, 그 뒤 웹소켓이 **연결 2개**로 붙어 31종목
전부 실시간 1분봉이 들어왔다. 이후 1분봉이 하루 약 4.5만 행(31종목)씩 는다.

**이력 깊이(오래된 존 기억)**: 팔 종목은 상위TF 이력을 **2년치**(`ALPHABLOCK_LIVE_ZONE_MEMORY_DAYS`, 기본 730일)
갖춘다. 정본은 몇 년 된 오더블록에도 들어가기 때문이다(정본 팔 후보의 98.4%가 존 나이 730일 이내). 새 종목은
처음부터 2년치를 받고(종목당 수십 초 · 그 뒤 재접속), 이미 모으던 종목은 백그라운드로 뒤로 늘린다(첫 기동에
31종목이면 십수 분 · 쪽당 0.2초 간격). DB는 약 300MB 더 는다(추정). 러너는 팔을 켠 뒤 처음 기동할 때 시리즈마다
2년치로 한 번 탐지한다(서버 약 10분 추정 · 재시작 때는 스냅샷에서 기억을 되살려 다시 안 한다).

## 확인

```bash
uv run alphablock universe
```

- 이번 주 31종목과 30일 평균 거래대금, 목록 밖 다음 순위 5개가 나온다.
- 지난주 대비 들어온 종목과 빠진 종목도 함께 나온다.
- 이번 주 목록이 없으면 **종료 코드 1**이다. 이때는 가장 최근 목록과 경고를 보여 준다.
- 지난 주를 보려면 `--at 2026-10-05`(UTC 날짜)를 붙인다.

수집 로그에서 진행을 본다.

```bash
journalctl -u alphablock-collector --since "15 min ago" | grep -E "후보 풀|종목 목록|팔 종목|팔 수집|웹소켓 접속"
```

`팔 종목 수집 계획: 팔 31종목 · 스트림 279개`와 `웹소켓 접속: … 연결 2개`가 보이면 정상이다.

## 알아 둘 것

- **검산**: 백테스트 정본은 일봉을 2019-06부터 읽고, 페이퍼는 메모리를 아끼려고 최근 400일만 읽는다.
  정본 53종목 풀로 2020-09 ~ 2026-07의 **306주 전부**에서 두 방식의 목록이 같았다(차이 0주).
- 나이(90일)는 **저장된 첫 일봉** 기준이다(정본과 같다). 신규 종목은 상장일부터 받으므로 같고,
  오래된 종목은 룩백 시작(1,825일 전)이 첫 봉이라 어차피 90일을 넘는다.
- 이 목록 테이블(`universe_rotations` · `universe_ranks`)은 장부가 아니라 시장 기록이라
  `paper-reset.sh`가 지우지 않는다.
- 실거래 보류는 그대로다(`ALPHABLOCK_LIVE_TRADING=false`).
