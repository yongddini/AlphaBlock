# 팔 종목 목록 켜기 — WAN-451 ③ 단계(종목 풀 · 매주 목록)

스토캐스틱 팔이 매매할 종목을 **매주 월요일 00:00 UTC(KST 09:00)** 에 정하는 부분이다.
이것만 켜서는 **매매가 하나도 안 바뀐다** — 수집기가 일봉을 더 모으고 목록을 DB에 남길 뿐이다.
1분봉 수집 종목과 러너 감시 종목을 이 목록으로 바꾸는 것은 다음 PR이다.

## 무엇을 하나

| 할 일 | 언제 | 무엇을 |
| -- | -- | -- |
| 후보 풀 일봉 수집 | 기동 직후 1번 · 매일 00:00 UTC + 2분 | 지금 상장된 USDT 무기한 **전체**(약 520종목)의 **1d만** REST로 |
| 이번 주 목록 계산 | 같은 때 · 이번 주 목록이 아직 없을 때만 | 직전 30일 평균 거래대금(`거래량 × 종가`) 상위 31종목 · 자격: 상장 90일 이상 · 마지막 일봉 3일 안 |
| 알림 | 새 주 목록을 저장할 때 1번 | 들어온 종목 · 빠진 종목(텔레그램 · 평문) |

- 규칙은 백테스트 정본과 **같은 함수**다(`data/universe.py`). 다른 것은 **후보 풀 하나**다.
  정본은 「2020-09-15 이전 상장 53종목 고정」이었고, 페이퍼는 「지금 상장된 전체」다
  (사용자 결정 ② 나, 2026-10-14). 이 풀로 돌린 백테스트는 없다.
- **한 번 저장한 주는 덮지 않는다.** 나중에 데이터가 바뀌어도 그 주에 실제로 고른 목록이 기록이다.
- 그 주 일요일 봉이 없는 종목이 풀의 10%를 넘으면(수집 실패) 저장하지 않고 **30분 뒤 다시** 한다.
  늦게 계산해도 월요일 00:00까지 닫힌 일봉만 읽으므로 결과는 같다.
- 빠진 종목의 보유 포지션은 유지하고 **새 진입만 막는다**(정본 `force_close=False`).
  이 막기는 다음 PR에서 러너에 붙는다.

## 켜기 (서버 · 사용자 수행)

```bash
cd ~/AlphaBlock && echo 'ALPHABLOCK_UNIVERSE_ENABLED=true' >> .env
```

```bash
sudo systemctl restart alphablock-collector
```

첫 적재는 풀 전체의 일봉 5년치다. 로컬 맥 실측(2026-10-15)은 **520종목 · 44.4만 행 · 342초 · 실패 0 ·
DB +50MB**였다. 다음 날부터는 새로 닫힌 일봉 하나씩이라 몇 분이면 끝난다. 스트림은 그 전에 붙는다(백그라운드).
요청 사이에 0.5초 간격을 둬서 바이낸스 요청 한도(분당 가중치 2400)를 넘지 않는다.

## 확인

```bash
uv run alphablock universe
```

- 이번 주 31종목과 30일 평균 거래대금, 목록 밖 다음 순위 5개가 나온다.
- 지난주 대비 들어온 종목과 빠진 종목도 함께 나온다.
- 이번 주 목록이 없으면 **종료 코드 1**이다. 이때는 가장 최근 목록과 경고를 보여 준다.
- 지난 주를 보려면 `--at 2026-10-05`(UTC 날짜)를 붙인다.

수집 로그에서 진행을 본다.

```bash
journalctl -u alphablock-collector --since "15 min ago" | grep -E "후보 풀|종목 목록"
```

## 알아 둘 것

- **검산**: 백테스트 정본은 일봉을 2019-06부터 읽고, 페이퍼는 메모리를 아끼려고 최근 400일만 읽는다.
  정본 53종목 풀로 2020-09 ~ 2026-07의 **306주 전부**에서 두 방식의 목록이 같았다(차이 0주).
- 나이(90일)는 **저장된 첫 일봉** 기준이다(정본과 같다). 신규 종목은 상장일부터 받으므로 같고,
  오래된 종목은 룩백 시작(1,825일 전)이 첫 봉이라 어차피 90일을 넘는다.
- 이 목록 테이블(`universe_rotations` · `universe_ranks`)은 장부가 아니라 시장 기록이라
  `paper-reset.sh`가 지우지 않는다.
- 실거래 보류는 그대로다(`ALPHABLOCK_LIVE_TRADING=false`).
