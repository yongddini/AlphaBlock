# WAN-264 — 비용·체결 보수화 시 재진입 북 이득 잔존 (pen_5bp + 수수료/슬리피지 민감도)

**성격** 측정 전용(기본값·토대 불변 · `ALPHABLOCK_LIVE_TRADING=false` 유지). WAN-262(오늘
엔진)가 잰 재진입 북 이득(off→on 의 MDD·최대 동시 리스크·거래·칸별 수익)은 **전부**
`baseline`(닿으면 체결 낙관) 위의 값이었다. 이 이슈는 그 델타에 **체결 보수화**(`pen_5bp` =
관통 5bp 요구)와 **비용 현실화**(WAN-92 방향 — 테이커 4→5bp·슬리피지 스트레스)를 얹어
**얼마나 남나**를 잰다. 채택 기본값 그대로(`ConfluenceParams()`·`OrderBlockParams()`·채택 북
cap_only 5배) 돌리며 옛 핀을 하나도 물려받지 않는다.

**재현**

```

uv run python -m backtest.wan264_reentry_book_stress --tf 15m --append --jobs 9   # 15m 무거움
uv run python -m backtest.wan264_reentry_book_stress --from-csv                   # 요약만 재생성
```

## 1. 두 축은 성격이 다르다 (컴퓨트 최적화의 근거)

* **체결 렌즈**(`baseline` vs `pen_5bp`)는 **후보 집합**을 바꾼다 — 관통 벌점은 substep 체결
  판정(`ConfluenceParams.fill_penetration_bps`)에서 적용되므로 렌즈마다 후보 생성을 **다시**
  해야 한다. 이게 유일한 무거운 연산이다.
* **비용**(테이커/슬리피지 bp)은 후보에 **무관**하다 — `BookCell`은 「비용 미반영 원가 셋업」
  이고 비용은 시퀀싱(`_to_trade`)에서만 적용된다(TP·SL은 가격 이벤트라 비용이 그 시점을
  바꾸지 않는다). 그래서 렌즈당 한 번 생성한 후보를 **여러 비용에 재사용**한다 — 비용 축이
  사실상 공짜다.

배선은 옵트인(끄면 비트 재현): `wan169.run_cells(fill=)` · `book_cli.build_book_rows(fee_rate=·
maker_fee_rate=·slippage=)`. 회귀 테스트가 라벨이 아니라 **동작**으로 고정한다(`fill=None`·
`fee_rate=None` = 채택 기본값 비트 일치 · `pen_5bp`는 후보 진입가를 실제로 이동/제거 · 테이커
5bp는 청산 비용을 올려 수익을 바꾸되 거래 수는 불변).

## 2. 판정 — 재진입의 위험 증가는 낙관 가정의 산물이 아니다 (보수화에서 남고 커진다)

`all`(1h·2h·4h) 스코프 · oos_warm(주 수치) 재진입 off→on:

| 렌즈 · 비용 | MDD off→on | (Δ · 잔존) | 최대 동시 리스크 | (Δ · 잔존) | 청산 |
| -- | --: | --: | --: | --: | --: |
| baseline · base | 12.17% → 14.89% | +2.72%p · 기준 | 9.80% → 11.36% | +1.56%p · 기준 | 0 → 0 |
| baseline · taker5 | 12.35% → 15.22% | +2.86%p · 105% | 9.80% → 11.36% | +1.56%p · 100% | 0 → 0 |
| baseline · taker5_slip7 | 13.88% → 17.16% | +3.28%p · 120% | 9.81% → 11.36% | +1.56%p · 100% | 0 → 0 |
| **pen_5bp · base** | 13.75% → **19.39%** | **+5.63%p · 207%** | 9.83% → 11.39% | +1.56%p · 100% | 0 → 0 |
| pen_5bp · taker5 | 14.75% → 20.50% | +5.75%p · 211% | 9.83% → 11.39% | +1.56%p · 100% | 0 → 0 |
| pen_5bp · taker5_slip7 | 16.70% → 22.68% | +5.98%p · 220% | 9.83% → 11.39% | +1.56%p · 100% | 0 → 0 |

- 📌 **관통을 요구하면 재진입의 MDD 증가가 줄기는커녕 늘어난다** — off→on MDD 델타가 기준
  +2.72%p에서 `pen_5bp`에서 **+5.63%p(잔존 207%)** 로 커진다. `pen_5bp`가 off 팔(기본 재탭)의
  마진 체결을 더 많이 걷어내 그 완충이 얇아지는데, on 팔(재진입 얹음)의 낙폭은 더 크게
  벌어지기 때문이다(off MDD 12.17→13.75%p 상승 대비 on 14.89→19.39%p). 즉 재진입이 더하는
  거래는 **손실 쪽에서 마진 체결에 더 기댄다**(WAN-96/124 「마진 체결」 성질의 재진입 축 재현).
- 📌 **최대 동시 리스크 델타는 렌즈·비용에 거의 불변**(+1.56%p, 잔존 100%) · **청산은 6조합
  전부 0**. 위험 증가의 모양(동시 노출·청산 없음)은 안정적이고, 커지는 것은 낙폭이다.
- 📌 **겉보기 총수익 증가는 보수화에서 침식된다** — on 팔 총수익 3512%(baseline·base) →
  1922%(pen_5bp·base) → 1680%(pen_5bp·taker5). ⚠️ **복리 착시라 판정에서 뺀다**(WAN-213) —
  요지는 "재진입은 위험이 견고하고 보상이 취약하다"이다(WAN-262 판정 강화).

### TF별 (oos_warm)

| TF | MDD off→on(base·base) | pen_5bp 잔존 | 최대 동시 리스크 Δ | 거래 off→on |
| -- | --: | --: | --: | --: |
| 1h | +4.55%p | 97% | +1.00%p | 770 → 967 |
| 2h | +0.19%p | (분모 작음 — 원 델타로 읽음) | +1.55%p | 395 → 502 |
| 4h | +0.98%p | 100% | +0.38%p | 215 → 289 |

- 1h가 재진입 MDD 증가가 가장 크고(+4.55%p) 관통 요구에도 유지된다(97%). 4h도 유지(100%).
- ⚠️ **2h는 기준 MDD 델타가 +0.19%p로 0에 가까워 잔존율이 수백 %로 폭발**한다(303~494%) —
  그 셀은 잔존율이 아니라 **원 델타(%p)** 로 읽는다(작은 델타 나누기라 비율이 과장된다).
  리포트 코드가 이 주의를 표에 찍는다.

## 3. 성격 · 경고 (인용 규칙)

- ⚠️ **전부 `baseline`(닿으면 체결) 낙관을 조인 값이다** — `pen_5bp`는 **관통 벌점**이지 큐
  우선순위·부분 체결 모델이 아니다. 틱·호가(WAN-98)는 **Canceled**라 이 표로도 낙관이 완전히
  해소되지 않는다 — **상한을 조인 것**이지 실체결이 아니다.
- ⚠️ **「엣지가 있나」는 묻지 않는다** — 재진입 가격 효과를 채택 북에 얹은 전체 위험을 렌즈·
  비용으로 스트레스한 측정이다(WAN-261/262와 같은 질문). 「엣지 없음」(WAN-84/88/111/114/124/
  151/201)은 탭 기준 진입 판정이라 이 축과 별개다.
- ⚠️ **격리 값(WAN-231/242/243)과 셀 직접 비교 금지** — 격리는 1포지션·재진입만, 이 표는 북
  공유 자본이다. **총수익%는 복리 착시**(WAN-213) — 판단은 MDD·최대 동시 리스크·청산이다.
- **채택(재진입 기본값화)은 재-베이스라인 = 사용자 결정** · 개발자 임의 착수 금지. 기본값·
  토대 불변(측정 전용).

## 4. 범위 · 후속

- 📌 **15m은 별도 무거운 append 후속이다**(WAN-261 → WAN-262 선례와 같은 분할). 셀당 ~37분
  (WAN-203) × 2렌즈 × 9종목이라 이 PR은 1h·2h·4h를 낸다(WAN-261 PR #214가 정확히 그 스코프
  였고 15m은 WAN-262 PR #215로 append됐다). 모듈은 `--tf 15m --append`로 15m을 붙일 수 있게
  이미 배선돼 있고, 15m은 낙관 가정 최대 의존 TF(WAN-231/203)라 그 축의 잔존율이 이 표보다
  더 취약할 수 있다(측정 후 확인). 지금 무거운 15m 격자를 시간별 루틴 경계에 걸쳐 돌리면
  다음 실행의 OB 성능 테스트가 CPU 경합으로 흔들리므로(알려진 함정) 별도 실행으로 남긴다.
- 안 잰 것: `pen_5bp_drop_50`(옵션 · 5시드라 무거움 — `--fill`로 수동 확인 가능) · 큐 우선순위·
  부분 체결(WAN-98 Canceled) · 15m(위).
