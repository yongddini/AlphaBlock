# WAN-213: 레버리지 북(cap_only 5배)을 채택 기본 회계로 승격

**작성일** 2026-07-31 · **성격** 재-베이스라인(회계 모델 전환) — 프로젝트 최대 규모.
파라미터 하나가 아니라 **포지션 회계 자체**가 「동시 1포지션」에서 **레버리지 북**
(칸=(종목,TF)마다 1포지션 · 여러 칸 동시 · 한 지갑 공유 · cap_only 5배)로 바뀐다.

**사용자 결정** 2026-07-30: cap_only·5배를 고른 뒤 「고정 범위」를 묻자 **「전부 다」**
(북 기본 설정 + 백테스트 채택 엔진 승격 + 페이퍼 러너 배선). 페이퍼 러너는 별도 이슈
(WAN-171)로, 이 PR은 **백테스트 채택 + 리포트 파급**이다.

**근거** [WAN-180](wan180.md) 실측: 9종목·못 박은 6년에서 cap_only는 배수를 올려도 MDD가
거의 안 늘고(both 2배 18.9% → 5배 19.6%), **5배가 같은 낙폭으로 복리를 가장 많이 받는
지점**이다. 결합(combined)처럼 배수가 곧 위험 배수가 되지 않고, 거래당 리스크를 1배로
묶어 낙폭이 배수를 안 따라간다. 청산 트리거 0건.

## §1 엔진 채택 — `LeverageBookParams()` 기본값이 채택 북이다

`ConfluenceParams()`가 채택 전략을 내듯 **`LeverageBookParams()`가 채택 북을 낸다**:

```python
LeverageBookParams()  # == leverage_multiple=5.0, leverage_mode="cap_only"
```

- 📌 **클래스 기본값을 옮겼다**(repo 규약: 기본값 = 채택, 옛 값 = `LEGACY_*` 상수 + 명시
  핀 — WAN-159의 `LEGACY_MAX_ZONE_WIDTH_ATR`, WAN-132의 `LEGACY_BAND_BAR`와 같은 패턴).
  WAN-169 중립 기준점(배수 1.0 · combined)은 **`LEGACY_BOOK_PARAMS`** 상수로 뺐다 — 「칸
  하나짜리 북 = 채택 단일 포지션 시퀀서 비트 일치」 항등을 검정하는 코드가 그 상수를 쓴다.
- 📌 **인자 없는 `backtest.run`이 북을 돈다**. `--positions`가 분기점이다:
  - **미지정 + 채택 좌표만**(전략·비용·거래별 축 없음) → **채택 북**. 인자 없는 실행과
    정본 리포트(`--oos-warm`)가 여기 든다.
  - **미지정 + 전략/비용/거래별 축 있음**(`--tp-r`·`--fill`·`--trades`·`--walkforward` 등)
    → **per-cell 단일 포지션으로 자동 접힘**. 북은 그 축을 표현하지 못하므로(채택 기본값만),
    기존 per-cell 스윕이 매번 `--positions single` 없이도 예전 그대로 돈다(ergonomics).
  - `--positions book` → 채택 북(명시). 여기에 그 축을 함께 주면 **거부**한다(조용히 per-cell로
    접지 않는다 — 사용자가 북을 콕 집었으니 어긋남을 알린다, WAN-95 교훈).
  - `--positions single` → per-cell **동시 1포지션**(WAN-122까지의 채택 · 옛 리포트 대조용).
  - `--positions 3` → per-cell **동시 다중 포지션**(WAN-103 명목 상한 배수).
- 📌 **북은 칸을 가로지르는 공유 자본 회계**라 per-cell 행(심볼·TF마다 한 행)으로 표현되지
  않는다 — 요청된 모든 칸이 **한 지갑**을 나눠 쓰고 결과는 **구간당 집계 행 하나**다.
  그래서 북 모드는 per-cell 파이프라인(`run_grid_full` → `RunRow`)을 건드리지 않고 새
  모듈 **`backtest/book_cli.py`**로 분기한다(`--positions single`/숫자는 예전 경로 그대로).

### 검산 — wan180 채택 셀과 비트 일치 (완료기준)

`book_cli`는 측정 리포트가 쓰는 **정확히 같은 함수들**을 부른다:
`wan169.run_cells`(칸별 후보·따뜻한 경계) → `wan180.apply_funding_proxy`(신규 종목 BTC
대리) → `wan169._segment_cells`(구간별 칸) → `leverage_book.run_leverage_book`(공유 자본
배치). 따라서 CLI 북 경로는 wan180의 `nine/both/cap_only/5.0` 셀과 **구성상 비트 일치**한다
(따로 재현 로직을 짜면 갈라진다 — WAN-95/112/123의 조용한 실패를 피하는 유일한 방법이
코드 공유다).

- 🚨 **`tests/test_book_cli.py::test_book_cli_matches_wan180_aggregation_bit_for_bit`**가 이
  「구성상 같음」을 **실데이터 위에서** 못 박는다: 같은 payloads에서 `book_cli.build_book_rows`
  (채택 북)와 `wan180.build_rows`의 `nine/both/cap_only/5.0/full` 셀이 `total_return`·
  `num_trades`·`max_drawdown`·`win_rate`·`peak_concurrency`·`max_concurrent_risk`·스킵까지
  **비트 일치**. 창을 작게(BTC+ETH · 15m+1h · 3개월) 잡아 CI에서도 몇 초 안에 돈다.
- 📌 **6년·9종목·both 전체 셀의 비트 일치**는 세션에서 돌리기엔 무겁다(15m·6년 셀당 ~37분,
  메모리 참고). 재현 명령:
  ```
  uv run python -m backtest.wan180_leverage_book_nine          # 격자 재산출(검산 포함)
  uv run python -m backtest.run --positions book --tf 15m,1h   # 같은 both 좌표를 CLI로
  ```
  wan180 모듈 자체가 `verify_cells`(±1e-12)로 채택 엔진과의 배선을 검산하고, 위 작은-창
  테스트가 CLI 경로 == wan180 aggregation을 고정하므로, 둘을 합치면 CLI 북 == 채택 셀이다.

- ⚠️ **인자 없는 실행의 좌표는 3 TF다**(15m·1h·4h = `DEFAULT_TIMEFRAMES`, WAN-182). wan180이
  측정한 채택 셀은 **2 TF**(both = 15m·1h, 18칸)다 — 4h는 wan180 이후 WAN-182가 작업 TF로
  승격했다. 즉 **인자 없는 북(27칸)의 수치는 wan180이 재지 않은 새 값**이고, wan180 셀과
  비트 일치하는 것은 **같은 좌표(15m·1h)로 좁혔을 때**다(`--tf 15m,1h`). 4h 포함 북의
  정본 수치는 `backtest.run --positions book --oos-warm`(인자 없이)이 낸다.

## §3 warm/cold OOS 파리티 (선행 기술 조건)

[WAN-166](wan166.md) 따뜻한 연속 OOS는 애초 「B안 단일 포지션 전용」이었다. 북 경로에 이를
배선하는 것이 §1의 「채택 승격」이 정본 수치를 내는 선행 조건이었다 — **이미 풀려 있었다**:
wan169가 칸마다 full·is·oos 후보와 따뜻한 경계(`boundary_ms`)를 만들고, `_segment_cells`가
`oos_warm`을 full 후보에서 칸별 경계로 걸러(**straddle (b)** — 워밍업 셋업은 배치조차 안 함,
[WAN-169](wan169.md) 확정) 만든다. `book_cli`가 그 구간들을 그대로 노출한다:

- `--oos-warm` → `full`·`is`·**`oos_warm`(주 수치)**·`oos`(스트레스) 네 행. **정본 리포트 =
  `uv run python -m backtest.run --oos-warm`**(인자 없이 = 채택 북).
- `--oos` → `full`·`is`·`oos`.
- 인자 없음 → `full`.
- ⚠️ `--walkforward`·`--years`(미끄러지는 창)는 북 경로에 **아직 배선하지 않았다**(거부 —
  필요해지면 별도 이슈). 경계에 걸친 워밍업 포지션의 슬롯 점유는 모델링하지 않는다(WAN-166/
  169 규약 그대로 = 배치조차 안 함).

## §2 리포트 파급 — 재산출이 아니라 명시 핀

CLI 기본값 전환은 **`main()` 수준의 인자 없는 실행**만 바꾼다. 리포트 모듈(`wanNN_*.py`)은
CLI 기본을 타지 않고 `harness`를 직접 부르므로 대부분 무관하다. 실제 파급은 좁다:

- **`LeverageBookParams` 기본값 이동** → `wan169_leverage_book.py`가 배수만 주고 결합을 기본에
  맡기던 자리(`build_rows`)를 **`leverage_mode="combined"` 명시 핀**으로 고정했다(그 리포트는
  결합만 측정했다 — CSV가 조용히 cap_only로 돌지 않게). wan180은 이미 `mode`를 명시해 무변.
- **CLI 기본 실행을 per-cell로 전제하던 테스트** = 명시 핀. ⚠️ **전략 축을 준 스윕 테스트는
  ergonomic 자동-접힘 덕에 핀이 필요 없다** — 핀이 필요한 건 **좌표만 준(전략 축 없는) 실행이
  per-cell 표를 기대하던** 경우다:
  - `tests/test_run_cli.py`의 `main()` 기반 테스트(예: `--symbol BTCUSDT`만 주고 `return%`
    열을 기대) → `--positions single`. 전략 축이 있는 것은 자동 접힘이라 핀이 중복이나 무해.
  - `tests/test_run_detail_output.py`(거래별 출력) → `--positions single`(자동 접힘이라 중복).
  - `tests/test_run_regression_real_data.py::test_cli_defaults_reproduce_wan95_zone_limit_cell`
    → `--positions single`(단일 포지션 wan95 셀은 이제 그 경로다 · `_run`이 `run_grid`를
    직접 부르므로 대조 자체는 불변).
  - `tests/test_leverage_book.py`·`test_wan180_funding_proxy.py`의 중립-항등 테스트 →
    `LEGACY_BOOK_PARAMS`(또는 `leverage_mode="combined"` 명시).
- **회귀 테스트가 동작으로 고정**(라벨만 붙는 실패 방지, WAN-95 교훈): `test_book_cli.py`가
  인자 없는 CLI가 실제로 북을 도는지(칸이 한 지갑으로 접히는지)·북 모드가 전략/비용/거래별
  축을 **거부**하는지·wan180과 비트 일치하는지·warm/cold가 둘 다 나오는지를 잡는다.

## 🚨 사용자가 알고 가는 것 (이슈에서 이미 짚음)

- **레버리지는 알파가 아니라 위험의 모양만 바꾼다**([WAN-90](wan90.md)). 총수익 %(예: both
  full +12.77억%대)는 수천 거래 복리 착시라 **실현 수익이 아니다** — 판단 근거는 **MDD·최대
  동시 리스크**다. `BookRunRow`의 판정 열이 그 축(`max_drawdown`·`return_over_mdd`·
  `max_concurrent_risk`·`liquidation_events`)이다.
- **6년 MDD ~20%(5배)는 천장이 아니라 바닥선** — 창이 2020-09-15 시작(SOL 상장 하한)이라
  2018 약세장·2020-03 폭락 미포함. 신규 3종목(DOGE·LINK·LTC)은 펀딩 BTC 대리(WAN-180).
- 전부 `baseline`(낙관 체결) 위 값 · **「엣지 없음」([WAN-84](wan84.md)/88/111/114/124/151/
  201) 불변**(다른 질문) · 「선별 대 가격」 미분리([WAN-131](wan131.md)).
- **실거래는 계속 보류** — `ALPHABLOCK_LIVE_TRADING=false` 유지. 이 이슈는 백테스트 기본값
  전환이고 실주문 활성화가 아니다.
