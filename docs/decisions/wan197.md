# WAN-197 — 손절폭 가드(0.3%)를 존폭 필터 1.28 켠 오늘 엔진에서 켜고/끈 수익률 재측정

- **상태**: 측정 완료 · **기본값 불변**(`min_stop_distance_fraction=0.003` 유지).
- **판정**: **(c) TF에 갈린다** — 15m (a)이득 · 1h (c)무영향 · 4h (b)손해(표본 게이트 대조군).
- **정본 수치**: [`backtest/reports/wan197_summary.md`](../../backtest/reports/wan197_summary.md)
  (원본 CSV `backtest/reports/wan197_guard_grid.csv`).
- **재현**: `uv run python -m backtest.wan197_guard_with_filter --timeframes 1h` →
  `--timeframes 15m --append` → `--timeframes 4h --append`(요약만: `--from-csv`).

## 0. 무엇을 물었나 (사용자 질문 2026-07-26)

사용자: *"필터 키고 새로 재야 할 것 같은데?"*

[WAN-154](wan154.md) §3-B가 최소 손절폭 가드(0.3%)를 켜고/끈 수익률을 **오늘 엔진**에서
쟀지만, 그때 **존폭 필터를 끈 채**(`max_zone_width_atr=LEGACY`=None) 측정했다 — WAN-154는
필터를 후보 리스트로 직접 만들어 매칭 대조군과 겨루는 모듈이라 엔진 필터를 켜면 이중
필터가 되기 때문이다. 그 뒤 [WAN-159](wan159.md)가 **필터 1.28을 채택 기본값으로** 올렸으므로,
**지금 실제로 매매하는 엔진(필터 켜짐)에서 가드만 켜고 끈 깨끗한 비교가 없었다.**

가드와 필터가 정면충돌한다 — 둘 다 "좁은 것"을 향한다(필터는 좁은 존만, 가드는 짧은 손절을
거부). 그래서 필터가 켜진 오늘 엔진의 가드 효과는 WAN-154(필터 끈 판)의
「15m +3.3~+5.9%p · 1h 무영향」과 다를 수 있었다.

## 1. 방법 — 새 파이프라인이 아니라 축 하나

모듈 [`backtest/wan197_guard_with_filter.py`](../../backtest/wan197_guard_with_filter.py)는
`trade_stats`·`per_trade_records`·`apply_guard`·`symbol_mean` 골격을
`backtest.wan152_selection_vs_geometry`에서 그대로 가져온다(새 파이프라인 금지 = WAN-154 사양
계승). WAN-152/154와 달리 **필터를 후보로 만들지 않는다** — 엔진의 채택 기본값
(`harness.build_params()` → `max_zone_width_atr=1.28`)이 후보를 이미 걸러 냈고, 그 `default`
팔(= 필터 켜진 채택 엔진 = 인자 없는 `backtest.run`) 위에서 **가드만** 스윕한다. 매칭
대조군·세 장벽은 여기 없다. 가드는 시퀀싱(`position_size`)에서만 걸리므로 후보를 (심볼,
TF)당 한 번만 빌드하고 값마다 재시퀀싱만 한다(체결 집합은 다섯 가드가 같다).

- **좌표**: 9종목 · 못 박은 6년 창(2020-09-15~2026-07-22, [WAN-182](wan182.md)) · 15m·1h·4h ·
  `baseline` 단독. 가드 축 = 0%(끔) · 0.22%/0.33%/0.55%(왕복 비용 0.11%의 2/3/5배) ·
  **0.3%(현행)**.
- **펀딩 대리(필수)**: 신규 3종목(DOGE·LINK·LTC)은 `funding_rate` 0행이라 [WAN-180](wan180.md)과
  같은 대리 규칙(기존 종목 중 확정 펀딩 평균 최고 = **BTC** 0.0067%/정산)을 얹는다. 안 얹으면
  펀딩비 0으로 그 종목 수익률이 부풀려진다.
- 🚨 **핀 미사용** — `LEGACY_*`·`pin_band_bar`를 쓰지 않는다(오늘의 채택 기본값 그대로).
  회귀 테스트가 후보 집합·구간 분할로 고정한다(WAN-152 패턴).
- 🚨 **`default` 팔이 곧 채택 엔진임을 실데이터로 고정** — 후보 전체를 가드 0.3%로 시퀀싱한
  `total_return`·거래 수·MDD·승률이 `harness.run_once`(프로덕션 경로)와 **비트 단위로 같다**
  (`test_full_list_guard_default_reproduces_production`). 필터가 실제로 후보를 걷어내는 것도
  고정한다(켠 것 < 끈 것, `test_filter_on_yields_fewer_candidates_than_off`).

## 2. 판정 — 필터 켠 상태에서 가드(0.3%)가 이득인가 (OOS · `default` 팔)

정본은 [`wan197_summary.md`](../../backtest/reports/wan197_summary.md) §판정.

| TF | 수익 끔 → 0.3% | Δ | 수익/MDD 끔 → 0.3% | 가드 탈락률 | 판정 |
| -- | -- | -- | -- | -- | -- |
| **1h** | +18.41% → +18.36% | −0.05%p | 3.12 → 3.14 | 10.7% | **(c) 중립(무영향)** |
| **15m** | +36.13% → +37.00% | +0.87%p | 4.55 → **6.16** | 38.5% | **(a) 이득** |
| **4h** | +8.52% → +8.35% | −0.17%p | 2.57 → 2.52 | 3.8% | **(b) 손해**(표본 게이트) |

**종합 (c) TF에 갈린다.** 하나의 가드 값이 세 TF를 동시에 좋게 하지 않는다 — 기본값을
유지한다(TF마다 다른 가드는 IS에서 고르는 자유 파라미터, WAN-108/143이 경계한 자리).

## 3. 필터를 켜니 무엇이 달라졌나 — 「같은 방향 두 번 자르기」의 실측

- **15m: 가드는 여전히 제 일을 한다(위험조정).** `total_return` 이득은 필터 끈 WAN-154판보다
  **작아졌지만**(+0.87%p) **수익/MDD가 4.55 → 6.16으로 뚜렷이 오르고 MDD가 7.93% → 6.00%로
  내린다.** 필터가 이미 좁은 존을 골라도 가드는 그 안에서 **가장 좁은 손절**(비용이 신호를
  먹는 거래)을 더 쳐낸다 — 후보의 38.5%. 가드는 수익 장치가 아니라 신뢰성 장치라는 WAN-76
  취지가 필터 켠 엔진에서도 성립한다.
- **1h: 무영향(WAN-154와 같다).** 가드가 후보의 10.7%만 건드리고 수익·위험조정이 사실상
  불변이다. 1h는 손절폭이 넓어(가드 탈락률이 낮아) 가드에 걸리는 거래가 적다.
- **4h: (b) 손해이되 대조군이다.** OOS 심볼당 거래가 적어 **BTC(15거래)·LINK(19거래)가
  20건 게이트에 걸려 유효 심볼이 7개**다. 가드 탈락률 3.8%로 거의 안 걸리고 Δ가 −0.17%p로
  0 언저리라, "손해"보다 "무영향에 가까운데 부호가 살짝 음수"로 읽는 게 정직하다. 표본
  게이트가 코드로 이 셀을 대조군으로 찍는다.

📌 **가드는 좁은 존 종목을 죽이지 않고 오히려 구한다 — 이슈의 붕괴 우려는 뒤집혔다.**
이슈는 WAN-154 `zone` 장벽 TRX 15m 붕괴(16거래)를 근거로 좁은 존 종목의 표본이 무너질까
걱정했다. 실측은 반대다:
- **TRX 15m**: 가드가 후보의 79.5%를 쳐내 372 → 79거래로 줄지만 **20건 게이트는 통과**하고
  (필터 1.28은 WAN-154의 분위 1/3 필터보다 후보를 덜 줄여 베이스가 크다), **수익이
  −15.52% → −0.28%로 +15.24%p 회복**한다. 가드가 자른 것이 큰 손실의 원천이었다.
- **BTC 15m**: +0.37% → +5.19%(+4.82%p), 가드 탈락률 62.6%. 역시 가드가 손실 거래를 쳐낸다.
- 반대로 **LINK 15m**: +74.82% → +62.37%(−12.45%p) — 가드가 좋은 좁은-손절 거래도 함께
  자른다. 그래서 15m은 종목에 갈리되 심볼평균은 이득이다(leave-one-out에서 어느 종목을 빼도
  가드 0.3% ≈ 끔, **ETH 편중 아님**).
- **실제 20건 붕괴는 4h OOS에서만**(BTC·LINK) 났다 — 좁은 존이 아니라 **긴 TF의 표본 희소성**
  탓이다.

## 4. 무엇을 바꾸지 않았나 · 인용 경고

- **측정 전용 · 기본값 변경 아님.** `ConfluenceParams()` 불변, `min_stop_distance_fraction
  =0.003` 불변, 토대(오프셋 2bp · `intrabar_live` · `unconditional` · 고정 1.5R · 롱 온리 ·
  `combine_obs=False` · 필터 1.28) 불변, 실거래 보류 `ALPHABLOCK_LIVE_TRADING=false` 유지.
  가드 기본값(0.3%) 전환은 [WAN-76](wan76.md)/79 소관이고 재-베이스라인 = **사용자 결정**이다.
- 🚨 **「엣지 찾았다」로 인용 금지** — 전부 `baseline`(닿으면 체결 = 낙관) 렌즈 위의 값이고,
  존폭·손절폭 축 체결 보수화(`pen_5bp`)는 이 이슈에서 안 쟀다(WAN-154 §4 참고). 「엣지 없음」
  (WAN-84/88/111/114/124/151)은 다른 질문(진입 규칙 vs 무작위)이라 뒤집히지 않는다.
- ⚠️ **OOS 규약은 전체창 후보를 시각으로 가른 「따뜻한」 판**(sweep 계열 = WAN-155/161)이다 —
  탭 시각이 IS 경계 이후인 후보만 신선한 초기자본으로 시퀀싱하되 OB 탐지는 전 창을 본다.
  slice-then-run(차가운 절단, WAN-89/145/151/164)과 **OOS 절대 수준을 나란히 인용하지 말 것**.
  단 가드 켜고/끈 대조는 같은 규약 안이라 이 규약 선택이 판정을 편향시키지 않는다.
- 🚫 WAN-76/79 원 감사 수치는 **옛 엔진**이라 이 표와 섞지 말 것.
