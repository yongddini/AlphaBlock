# WAN-309 — `.env`가 채택 좌표를 조용히 덮는다: 드리프트 점검 + 기동 시 경고

- **일자**: 2026-08-15
- **성격**: 운영/안전 — 「라벨과 동작이 어긋나는 조용한 실패」(WAN-91/95/112/123/159 부류)의
  **운영 계층 판**을 코드가 찍게 한다. 엔진·기본값·토대 불변, `.env`는 코드가 절대 수정하지
  않는다, `ALPHABLOCK_LIVE_TRADING=false` 유지.
- **관계**: WAN-307(유니버스 9→12 — 이 문제를 드러낸 계기) · WAN-191(감시 확대 — 로컬
  `.env`가 이 결정 이전에서 멈춰 있다) · WAN-252/246(2h 승격) · WAN-194(`alphablock
  doctor` — 붙인 자리) · WAN-174(서버 운영) · WAN-308(좌표 단절선, 자매 축).

## 0. 실태 확인 (§0) — 노트북 실측 · 서버는 도구로 넘김

**이 노트북(로컬 저장소 폴더)의 `.env`는 2026-07-22 23:23 KST자이고, 좌표 3+1개가 낡은
값으로 명시돼 있다** (2026-08-15 실측, 새 `check_coordinate_drift` 출력 그대로):

| 키 | `.env` 실효값 | 채택 좌표(코드 기본값) | 어긋남 |
| -- | -- | -- | -- |
| `ALPHABLOCK_SYMBOLS` | 9종목 | 12종목(WAN-307) | **누락: ADA·DOT·BCH** |
| `ALPHABLOCK_TIMEFRAMES` | `["1m","15m","1h","4h","1d"]` | + `5m` | **누락: 5m** — WAN-195의 「5m 유일본」 사연과 정합(수집 목록에서 빠져 있었다) |
| `ALPHABLOCK_LIVE_SIGNAL_SYMBOLS` | `["BTC/USDT:USDT"]` | 12종목 상속 | **BTC 단독**(WAN-191 이전) |
| `ALPHABLOCK_LIVE_SIGNAL_TIMEFRAMES` | `["1h"]` | 15m·1h·2h·4h | **1h 단독**(WAN-191/252 이전) |

`ALPHABLOCK_LIVE_TRADING=false`는 그대로다(안전 게이트 정상).

**어느 기계가 도는가**: 이 노트북의 하트비트는 `collector_heartbeat.json` 07-22 22:48 ·
`live_runtime_state.json` 07-24 14:07에서 멈춰 있다 — **이 노트북에서는 수집기·러너가 돌고
있지 않다**. 실제 페이퍼 러너·수집기는 서버(WAN-174)에 있고 **그 기계의 `.env`는 여기서 볼
수 없다**(이 환경은 서버 SSH가 없다 — WAN-195와 같은 제약). 그래서 서버 몫은 사람이 서버에서
한 줄 돌리는 것으로 넘긴다: **이 이슈가 배선한 경고가 곧 그 확인 도구다** — 배포 후 서버에서
`alphablock status`(또는 `doctor`, 또는 수집기·러너 재시작 로그)를 보면 그 기계의 실효
설정과 채택 좌표의 어긋남이 그대로 찍힌다. 수동으로 `.env`를 눈으로 대조할 필요가 없다.

⚠️ **노트북 `.env`도 이 이슈가 고치지 않았다** — 완료 기준 4(「`.env` 자체는 코드가 수정하지
않는다」)와 범위 밖 규정(「실제 값 변경은 사용자가 한다」) 그대로다. 로컬은 러너가 돌지 않아
당장 사고가 아니지만, 이 폴더에서 수집기를 다시 켜면 위 표의 좌표로 돈다 — 그 순간 경고가
찍히는 것이 이번 배선의 목적이다.

## 1. 기동 시 드리프트 경고 (§1) — 새 모듈 `config/drift.py`

`check_coordinate_drift(settings)`가 좌표 필드 4개(`symbols`·`timeframes`·
`live_signal_symbols`·`live_signal_timeframes`)의 **실효값 ↔ 코드 기본값**을 대조한다.
어디가 덮어썼는지(셸 env냐 `.env`냐)는 묻지 않는다 — 실효값이 채택 좌표와 다르면 그 자체가
알릴 사실이다. 순서만 다르고 집합이 같으면 드리프트가 아니다(좌표 필드는 순서 무의미).

- **채택 좌표를 복붙하지 않는다** — `Settings.model_fields[...].get_default(
  call_default_factory=True)`로 pydantic 필드 정의에서 읽으므로, 다음 재-베이스라인이
  코드 기본값을 옮기면 드리프트 점검이 **자동으로 새 좌표를 따라간다**(이 이슈가 막으려는
  실패를 이 모듈 자신이 반복하지 않게).
- **배선 4곳**: 수집기 기동(`data.collector.run_collector` — `logger.warning`) · 러너 기동
  (`live.runner.run_signal_runner`) · `alphablock status`(요약 뒤 경고 블록) ·
  `alphablock doctor`(점검 머리에 「환경 설정 드리프트」 섹션). **일치하면 아무것도 안
  찍는다**(회귀 테스트가 동작으로 고정).
- **자동으로 덮어쓰지 않는다** — env를 존중하고 보이게만 한다. 경고 꼬리에 「의도한 축소가
  아니라면 `.env`를 갱신하고 재시작하라, 코드는 값을 자동으로 고치지 않는다」를 명시.
- **doctor 종료 코드에는 반영하지 않는다**(이슈가 개발자 판단으로 넘긴 항목): 좁혀서 테스트
  중일 수 있는 의도된 차이라 경고이지 에러가 아니고, doctor의 exit 1은 DB 무결성 판정
  (`report.healthy`) 전용으로 남긴다 — 드리프트가 exit 1을 내면 cron 감시가 「DB 손상」과
  「낡은 .env」를 구분 못 하게 된다.

## 2. `.env.example` ↔ `.env` 키 대조 (§2)

`env_example_only_keys()`가 `.env.example`에는 있는데 `.env`에는 없는 키 **이름**을 모아
`doctor`가 한 줄로 찍는다(2026-08-15 로컬 실측 **19개** — 이슈 본문의 개수와 일치:
`BACKTEST_JOBS`(WAN-294) · 틱 피드 2개(WAN-256) · 재진입 규칙(WAN-273/274) · 따라잡기
한도(WAN-306) · 수집기 워치독 4개(WAN-173) · 시작 복구 3개(WAN-35/187) · 대시보드 2개 ·
페이퍼 알림 2개 · 백테스트 펀딩 2개). **없는 키는 코드 기본값을 따르므로 대부분 문제가
아니다** — 목록의 목적은 「의도적으로 비움」과 「몰라서 빠짐」의 구분을 가능하게 하는 것.
어느 한쪽 파일이 없으면 대조 불가로 조용히 생략한다(`.env` 없이 코드 기본값으로 도는 기계는
정의상 드리프트가 없다). **값은 절대 출력하지 않는다** — 키 이름만(비밀값 보호).

부수: `.env.example`의 `ALPHABLOCK_SYMBOLS` 예시가 아직 9종목(WAN-307 이전)이라 **예시
자체가 드리프트 소스**였다 — 12종목으로 갱신하고, 「이 키를 박아 두면 이후 재-베이스라인이
적용되지 않는다」 경고를 달았다.

## 3. 파급 · 안 한 것

- 엔진·백테스트 경로 무변 — 이슈 본문이 「착수 시 확인」으로 남긴 항목의 답: 백테스트 좌표
  (`backtest/harness.py:83`의 `DEFAULT_SYMBOLS` 등)는 **모듈 상수**라 `.env`의 영향을 받지
  않는다(harness가 설정을 읽는 곳은 `backtest_jobs` 하나 — 성능 노브이지 결과 축이 아니다,
  WAN-121/294). 즉 이슈가 경고한 「백테스트는 12종목·수집기는 9종목」 조합이 실제 구조다 —
  위험한 것은 수집·감시 계층뿐이고 그곳에 배선했다.
- 서버 `.env`의 실제 값 확인·수정은 **사용자 몫**(범위 밖 규정) — 도구는 배선됐고, 서버에서
  `alphablock status` 한 번이면 드리프트가 보인다.
- 텔레그램 경고로 승격(드리프트를 폰으로)은 하지 않았다 — 기동 시 로그·점검 출력까지가 이슈
  범위. 필요하면 별도 이슈.
