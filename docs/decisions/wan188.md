# WAN-188 — 분석 탭 성능: 기본 창 축소 + 표시선 기본 꺼짐 + 디스크 캐시

**표현 계층 전용이다.** 엔진·토대·전략 로직·실거래 플래그를 하나도 건드리지 않았다
(`ConfluenceParams()` 불변 · `ALPHABLOCK_LIVE_TRADING=false` 유지). **같은 창에서 화면
숫자·거래는 예전과 같다** — 회귀 테스트가 동작으로 고정한다.

사용자 관찰(2026-07-24): *"기본적으로 대시보드가 너무 느려 진짜 너무 느려."* 그리고
*"몇 년 전 데이터는 다들 똑같이 있을 거 아냐"*(= 안 바뀌는 옛 구간을 매번 다시 계산할
이유가 없다).

## 0. 측정이 먼저다 — 그리고 가정 하나가 틀렸다

실측 환경: `BNB/USDT:USDT` · `15m` · 6년(210,238봉) · 3.5GB DB. **BNB 15m이 곧 첫 화면**
이다(심볼·TF 셀렉트박스가 정렬 순 첫 항목을 고르므로 최악이 기본값이었다).

| 항목 | 전 구간(옛 기본) | 최근 180일(새 기본) |
| --- | ---: | ---: |
| 봉 수 | 210,238 | 17,281 |
| 탐지+백테스트 | 6.77s | 0.25s |
| 차트 페이로드 (표시선 ON) | **75.65 MB** | 6.41 MB |
| 차트 페이로드 (표시선 OFF) | 31.72 MB | **2.79 MB** |

- 📌 **표시선 6개가 페이로드의 58%다**(75.65 → 31.72MB). 이슈가 "공짜에 가까운 개선"이라
  본 그 항목이 실제로 가장 큰 단일 조각이었다.
- 📌 **이슈의 추정(≈70MB)이 거의 정확했다**(실측 75.65MB).
- ⚠️ **틀린 가정 하나**: "전 구간 로드가 병목"일 것 같았으나 **0.52초**다(SQLite 인덱스가
  빠르다). 병목은 로드가 아니라 **탐지·백테스트(6.77s)와 브라우저로 보내는 75MB**였다.
  그래서 이 이슈의 주된 이득은 "로드를 줄여서"가 아니라 **"계산과 전송을 줄여서"** 온다.

## 1. 한 것 세 가지

**① 기본 기간 = 최근 180일**(`_DEFAULT_WINDOW_DAYS`). 전 구간은 **옵트인 체크박스**
(`전 구간 보기(느림)`)로 남는다 — 옛 구간을 볼 길을 없앤 게 아니다.
⚠️ 켰을 때 창이 **실제로** 넓어지는지를 테스트가 고정한다(라벨만 바뀌고 동작은 그대로인
WAN-91/95/112/123 부류 방지).

**② 표시선(EMA 20/60/120/240/365 + VWMA 100) 기본 꺼짐.** 채택 규칙은 이 선들을 **하나도
쓰지 않는다**(RSI 게이트 없음 WAN-123 · 익절 고정 1.5R이라 `use_line_take_profit=False`).
정보 손실 0이고 체크박스로 언제든 켠다.
⚠️ **진입 기준선인 볼린저 하단선은 이 토글과 무관하게 계속 그려진다** — `build_chart_html`이
`deviation_filter`에서 따로 만든다. 끄는 것은 장식뿐이다.

**③ 파이프라인 결과 디스크 캐시**(`dashboard/analysis_cache.py`) — 사용자 직관의 구현.
`st.cache_data`는 프로세스가 살아 있는 동안만 유효해 대시보드를 다시 띄우면 6년 구간을
통째로 다시 계산했다. gzip JSON 한 파일(6년 15m = 2.2MB)로 그 재계산을 **6.80s → 0.89s**로
줄인다.

**부수**: 기간 위젯 범위를 잡으려고 **전 구간을 로드하던 것**을 `MIN`/`MAX` 인덱스 조회로
바꿨다(`series_bounds`, 0.52s·19MB → 0.002s). 파생 TF(`2h`)는 저장소에 행이 없어 그때만
리샘플 로드로 물러난다.

## 2. 결과 (실측, 같은 기계)

| | 계산 | 페이로드 | 봉 수 |
| --- | ---: | ---: | ---: |
| **전(6년 + 표시선 6개)** | 7.10s | 75.65 MB | 210,238 |
| **후(180일 + 표시선 끔) 냉시작** | 0.57s | 2.79 MB | 17,281 |
| **후(180일 + 표시선 끔) 캐시 적중** | **0.03s** | 2.79 MB | 17,281 |

→ 계산 **12.5배**(냉시작) · **269배**(캐시 적중) · 페이로드 **27.1배** 감소.

**같은 창에서 숫자는 같다**(검산): 냉시작 · 캐시 적중 · 재계산 셋의
`BacktestMetrics`·거래 목록이 **전부 일치**(161거래 · −20.23%).

## 3. 캐시가 옛 결과를 잘못 꺼내지 않게 하는 장치 (WAN-106 원칙)

파라미터만으로 키를 만들면 **엔진 버그를 고쳐도 키가 같아 옛 결과가 나온다** — 이 저장소가
반복해서 당한 조용한 실패다. 그래서:

- 키 = `SHA-256(캐시 버전 · 심볼 · TF · 창 · 파라미터 직렬화 · **코드 리비전**)`.
- `cache_key(revision=...)`는 **기본값이 없다** — 호출부가 잊으면 캐시가 조용히 낡는 대신
  `TypeError`가 난다(테스트가 이 성질 자체를 고정한다).
- `CACHE_VERSION`은 `PipelineResult`의 **의미**가 바뀌면 손으로 올린다.
- 캐시는 DB 옆(`<db 디렉터리>/cache/analysis/`)에 산다 — DB를 갈아끼우면 캐시도 갈라지고,
  `data/cache/`는 이미 `.gitignore` 대상이다. 테스트의 `tmp_path` DB는 저절로 격리된다.
- 손상·구버전 파일은 **예외가 아니라 캐시 미스**다(다시 계산한다). 쓰기는 임시 파일 →
  원자적 교체라 반쯤 쓰인 파일을 다음 실행이 읽지 않는다.

## 4. 주의 · 안 한 것

- ⚠️ **기본 창이 바뀌었으므로 「첫 화면의 숫자」는 예전과 다르다** — 구간이 다르니 당연하다.
  불변인 것은 **같은 창을 골랐을 때의 숫자**이고, 그게 회귀 테스트가 고정하는 성질이다.
- ⚠️ **분석 탭은 여전히 A안(종가 진입)이다** — 상위TF만 로드해 1분봉 서브스텝을 못 돌린다
  (WAN-95). 이 이슈는 그 성질을 건드리지 않았다(배지도 그대로 "A안(봉 마감 종가)").
- **이슈 ①의 "trade_store로 옮긴다"는 문자 그대로 하지 않았다** — `trade_store`는 거래·
  셋업·시드곡선을 담고 **오더블록 존은 담지 않는다**(그래서 「저장된 거래」 탭이 존을 안
  그린다). 분석 탭의 존재 이유가 존 차트라 그대로 옮기면 그 탭이 「저장된 거래」 탭과
  같아진다. 그래서 **같은 원칙(지문 + 코드 리비전)으로 저장·조회하되 저장 대상이
  `PipelineResult`인** 별도 캐시를 만들었다. 완료 기준의 "전 구간 재계산 제거 **또는** 저장
  결과 조회로 전환"을 둘 다 만족한다.
- **차트의 지연 로딩은 이미 있다**(`build_chart_html(initial_bars=1500)`) — 다만 그건
  **렌더**만 지연이고 **전송**은 통째였다. 이 이슈는 전송량 자체를 창으로 줄였다. 전송의
  청크 지연 로딩(WAN-60)은 범위 밖이다.
- 캐시 파일은 (심볼 × TF × 창 × 파라미터 × 리비전)마다 하나씩 쌓인다(6년 15m = 2.2MB).
  자동 청소는 넣지 않았다 — 지우면 다시 계산할 뿐이라 안전하다.
