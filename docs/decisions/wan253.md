# WAN-253: 당일 타임라인 캐시 키를 「레포 전체 git 해시」→「엔진 소스 지문」으로 좁힌다

**성격: 순수 도구/캐시 정밀화.** WAN-239(당일 타임라인 캐시)가 실행 지문에 실은 자동
리비전 축을 **레포 HEAD의 git 짧은 해시(`engine_revision()`)** 에서 **백테 결과를 바꿀 수
있는 소스 파일의 내용 해시(`engine_source_revision()`, `eng:…`)** 로 바꾼다. **엔진·전략·
기본값·토대는 안 건드린다**(`ConfluenceParams()` 등 불변, `ALPHABLOCK_LIVE_TRADING=false`
유지). 캐시가 **무엇을 계산하는지**는 그대로다 — **언제 무효화되는지**만 좁힌다.

## 배경 — 사용자 지적 (2026-08-05)

당일 거래별 타임라인의 백테 대조 캐시(WAN-239)는 `run_id` 지문에 `engine_revision()` =
**레포 HEAD git 해시**를 넣었다. 그래서 **백테 결과와 무관한 커밋**(대시보드 UI·리포트
스크립트·PM 도구·문서 오타 하나)만 바꿔도 해시가 달라져 어제 야간 크론이 쌓은 캐시가
**통째로 무효**가 됐다. 실제 증상: 서버 대시보드가 `28142b9`에서 도는데 캐시는 `c8f7ad6`
에서 쌓여 있어 **6/6 전부 미스**. 사용자 원문: **"매번 소스는 바뀔 수 있는데 어떡하니."**

WAN-106의 **의도는 유효하다** — "엔진 버그를 파라미터 불변인 채 고치면 백테 숫자가 달라질
수 있으니 옛 캐시를 꺼내주면 안 된다"(WAN-91/95/112의 "바꿨다고 믿으면서 안 바뀐" 방어).
문제는 그 안전장치로 **레포 전체 HEAD 해시**를 쓴 것이 **너무 뭉툭**했다는 것이다. 채택
파라미터(`confluence_json`·`order_block_json`·`config_json`)는 **이미 지문에 들어 있으므로**,
캐시를 깨던 유일한 잉여 축은 저 레포 전체 git 해시 하나였다.

## §1 엔진 소스 지문으로 교체

`backtest/trade_store.py`에 `engine_source_revision()`을 추가했다:

* **입력** = `ENGINE_SOURCE_FILES`(레포 상대 경로, 정렬 고정)의 각 파일 **내용 + 경로**를
  고정 순서로 SHA-256에 흘려 앞 12자를 `eng:` 접두와 함께 낸다.
* **워킹트리 기준**이라 커밋 전 편집도 즉시 반영된다(git subtree 오브젝트 해시가 아니라
  **파일 내용**을 직접 읽는다). `git` 없이도 동작한다.
* 목록의 파일을 못 읽으면(삭제·비-레포) `UNKNOWN_REVISION`(`"unknown"`)으로 접어 적재를
  막지 않되 "모른다"를 남긴다(`engine_revision`과 같은 규약).

`engine_revision()`(레포 HEAD 해시)은 **삭제하지 않았다** — 대시보드 분석 캐시(WAN-188,
`dashboard.app._cached_revision`)와 백테 DB 적재 지문(`RunFingerprint`, WAN-106의
`backtest.run --persist`)이 여전히 쓴다. 이 이슈는 **WAN-239 타임라인 캐시의 리비전 축만**
좁힌다(범위 밖: `RunFingerprint`로의 확장은 후속 여지).

### 무엇이 「엔진」인가 — `ENGINE_SOURCE_FILES` (이 축의 위험 중심)

「백테 결과를 바꿀 수 있는 소스」로 **포함**(err toward inclusion — 애매하면 엔진으로):

| 트리 | 엔진 파일 |
| -- | -- |
| `strategy/` | `__init__` · `confluence` · `indicators` · `models` · `order_blocks` · `realtime_band` · `realtime_rsi` |
| `config/` | `__init__` · `settings` |
| `execution/` | `__init__` · `sizing` · `leverage` · `risk` |
| `backtest/` | `__init__` · `harness` · `models` · `metrics` · `portfolio` · `leverage_book` · `book_cli` · `multi_tf_overlap` · `substep` · `sweep` · `zone_limit_backtest` |

**비-엔진**(내용이 백테 수치에 안 실림 → 캐시 무효화하지 않음):

* `backtest/wan…` 리포트 모듈 · `backtest/archive/` · `backtest/reports/`
* `backtest/{run,trade_store,report,synthetic}.py`(CLI·저장·표시·합성 데이터)
* `execution/{broker,engine,models}.py`(**라이브 집행 전용** — 백테 계산 사슬이 안 읽는다.
  하필 WAN-45/171/241/235 라이브 작업이 자주 건드리는 파일이라, 여기 넣으면 라이브 PR마다
  캐시가 깨진다 → 의도적으로 비-엔진)
* `strategy/parity/` · `strategy/reference/`(QC 파리티 하네스·`.pine` 참조)
* 스캔 루트 밖 전부: `dashboard/` · `docs/` · `cli/` · `live/`(캐시 자신 포함) · `paper/` ·
  `data/` · `scripts/` · `qc/`

### §2-c 「엔진 파일 목록 누락」 가드 (WAN-106 공포를 동작으로 막는다)

목록에서 엔진 파일을 빠뜨리면 그 파일을 고쳐도 지문이 안 바뀌어 **stale을 조용히 서빙**
한다 — WAN-106이 뭉툭한 레포 해시를 쓴 이유가 바로 이 누락 공포다. `scan_engine_source_tree()`가
스캔 루트(`strategy`·`config`·`execution`·`backtest`)의 **모든** `.py`를 훑어 엔진 목록에도
`_is_declared_non_engine` 규칙에도 안 걸리는 파일을 **미분류**로 돌려준다. 회귀 테스트
`test_scan_real_repo_has_no_unclassified_files`가 실 레포에서 미분류 0을 강제하므로,
**새 엔진 파일을 목록 없이 추가하면 CI가 실패**한다(그때 개발자가 엔진/비-엔진을 결정해
넣어야 통과). 새 `wan…` 리포트는 규칙에 걸려 통과하므로 리포트 PR마다 깨지지 않는다.

## §2 회귀 테스트 (`tests/test_trade_store.py`)

* **(a)** `test_engine_source_revision_changes_when_engine_file_changes` — 엔진 파일 한 글자
  변경 → 지문 달라짐(캐시 키 무효화).
* **(b)** `test_engine_source_revision_stable_when_non_engine_changes` — 비-엔진(리포트·
  `run.py`·`execution/engine.py`·`strategy/parity`) + 스캔 루트 밖(`dashboard/`) 변경 →
  지문 불변(어제 캐시 그대로).
* **(c)** `test_scan_detects_unclassified_new_engine_file`(가짜 레포에 미분류 주입 → 잡힘) +
  `test_scan_real_repo_has_no_unclassified_files`(실 레포 미분류 0).
* 부수: 삭제 파일 → `"unknown"` 폴백 · 목록 정렬·존재 · `eng:` 접두·길이.

## §3 표시·마이그레이션

* **배지·라벨**: `TimelineCacheFingerprint.display_label` / `current_engine_label`이 이미
  `revision` 값을 (Ⅱ) 보조 키로 보여 주므로, 리비전 소스만 바뀌면 화면·CLI에 자동으로
  `eng:…`가 뜬다(대시보드 캡션·`alphablock trades` 라벨). `eng:` 접두가 옛 git 짧은 해시와
  화면에서 구분돼 "옛 엔진을 오늘 것인 양" 오독하는 사고를 막는다(WAN-239 완료기준 4-Ⅱ 유지).
  관련 docstring을 「git 해시」→「엔진 소스 지문」으로 갱신했다.
* **마이그레이션(재적재 1회 필요)**: 기존 캐시 셀은 옛 `run_id`(레포 git 해시 기반)라 새
  규칙에서 **자연히 미스**가 된다 — 조용한 폴백은 없으므로(WAN-239 그대로) 화면은 "아직 계산
  안 됨"을 명시하고, 야간 크론(또는 `alphablock trades --day <어제KST> --persist-cache`)이
  한 번 돌면 `eng:…` 키로 다시 쌓인다. 그 **한 번 이후로는** UI·리포트·문서·PM 배포가 캐시를
  깨지 않는다. 옛 셀 행은 남지만(이력 보존) 조회되지 않는다.
