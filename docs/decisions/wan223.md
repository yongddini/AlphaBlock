# WAN-223 §1 — 지정가 주문 관리 census (만료 후 재진입 구멍 · GO/STOP 게이트)

**성격** 측정 전용(기본값·토대 불변 · `ALPHABLOCK_LIVE_TRADING=false` 유지). 사용자 제안
(2026-07-31)의 「존 형성 즉시 대기 예약 + 가까운 주문 우선 배분」(§2)을 짓기 전에, 그 대기
모델이 **닫으려는 구멍의 크기**를 먼저 재는 GO/STOP 게이트다. 채택 기본값 그대로
(`ConfluenceParams()`·`OrderBlockParams()`) 돌리며 옛 핀(`LEGACY_*`)을 하나도 물려받지 않는다.

**재현**

```
uv run python -m backtest.wan223_limit_order_census --tf 4h,1h --jobs 6
uv run python -m backtest.wan223_limit_order_census --from-csv   # 요약만 재생성
```

원본: `backtest/reports/wan223_limit_order_census.csv` ·
요약: `backtest/reports/wan223_limit_order_census_summary.md`

## 1. 무엇을 쟀나 — 사용자가 짚은 구멍

지금 엔진은 지정가 주문을 **탭(바깥→안 전이) 순간**에 만들고 `limit_valid_bars`(채택 기본값
24봉, WAN-222)가 지나면 취소한다. 사용자 지적: *"취소하면 다음엔 못 건다"* — 주문이 만료로
취소된 뒤 가격이 곧 같은 존에 다시 닿았는데 「바깥→안」 새 탭이 없어(존 근처에 계속 머묾)
주문을 다시 걸지 못하는 재진입 유실. §1은 그 구멍의 **크기(빈도)** 만 잰다 — 대기 모델이
그 재진입을 잡아 **수익을 더하는지**는 §2를 지어 §3에서 대조해야 안다(이슈 한계 그대로).

## 2. 방법 — 두 패스 (유일 차이 = 유효기간)

같은 셋업 풀(같은 오더블록·같은 `retap_signals`)을 두 번 돌린다:

* **`base`** = 채택 기본값(`limit_valid_bars=24`).
* **`wait`** = 무기한 대기(`=None`, 존 무효화까지) = **형성-즉시 예약의 체결 대리**(만료 없는
  순수 대기 지정가).

**핵심 지표 = `filled_wait − filled_base`.** 두 패스의 셋업 집합이 동일하므로(재탭도 양쪽에
똑같이 들어 있다) 이 차이는 **재탭이 이미 복구한 체결을 뺀 순증** = 「재탭 실패로 놓친
재진입」의 크기 그 자체다. 같은 셋업이 24봉 안에 닿으면 무기한에서도(더 일찍) 닿으므로
`filled_wait ≥ filled_base`가 성립한다(무효화가 먼저 오면 두 패스가 똑같이 취소 — `substep`이
만료보다 무효화를 먼저 본다). 회귀 테스트가 판정 자(尺)와 동시대기 스위프라인을 고정한다
(`tests/test_wan223_limit_order_census.py`).

⚠️ **15m은 이 표에 없다** — 무기한 패스는 셋업을 무효화까지 스캔해 15m·6년에서 초선형으로
느리다(단일 15m 셀도 24봉 패스가 >2분, 무기한은 더). 4h·1h가 두 작업 TF의 대표이고, 15m 전
구간 재측정은 무거운 후속 컴퓨트로 남긴다. 4h·1h는 못 박은 6년 창에서 셀당 ~17s·~80s.

## 3. 결과 (9종목 × 4h·1h · 못 박은 6년 · `baseline` 단독)

| TF | 놓친 재진입 / 진입 | 비율 | 심볼평균 total_return (24봉→무기한) |
| -- | --: | --: | -- |
| 4h | 58 / 559 | **10.4%** | 31.3% → 32.9% (**+1.63%p**) |
| 1h | 267 / 2217 | **12.0%** | 108.1% → 118.8% (**+10.73%p**) |
| 합계 | 325 / 2776 | **11.7%** | (심볼평균) **+6.18%p** |

* **만료 자체가 드물지 않다** — eligible 셋업의 ~10~13%가 24봉 만료로 취소된다(4h 6~21건,
  1h 44~63건/종목). 그 만료 중 절반 안팎이 나중에 실제로 다시 닿아(무기한 패스가 체결)
  「놓친 재진입」이 된다.
* **놓친 재진입 ≈ 진입의 11.7%** — 무시할 수준(<5%)은 아니나 일상(≥20%)도 아니다.
* **늘어난 체결이 수익을 더하는가는 종목에 갈린다** — 1h는 심볼평균 +10.73%p지만 **LINK는
  오히려 89.8%→80.7%로 줄고**(체결 +25인데 수익 −9%p) BNB·DOGE 4h도 준다. WAN-222의 "더 오래
  걸어 두면 체결은 늘지만 수익이 따라오진 않는다"가 종목 단위로 재확인된다.

**§1b 진입 빈도(WAN-225 흡수)**: 채택 24봉·단일 포지션 기준 평균 진입 간격은 **4h ~28~41일 ·
1h ~7.6~9.7일**. 라이브에서 "이틀에 한 번" 같은 관찰이 정상 범위인지의 못 박은-창 기대값이다
(4h는 한 달에 한 번꼴이라 이틀 관찰로는 표본이 턱없이 작아 단정 불가).

**부가**: 슬롯거부(체결됐으나 칸이 포지션 중이라 진입 못함) 4h 7~19 · 1h 60~103건 —
칸 **안** 단일 포지션 회전 문제(북 아님). 동시대기 최대 5~7개 지정가/칸(24봉 지평 상한
근사). 칸을 가로지르는 **명목 상한 거부**는 북(WAN-213 cap_only 5배) 소관이고 WAN-180 실측
**6년 7건**으로 드물다 — 「가까운 주문 우선」 배분(§2)이 바꿀 여지는 그만큼 작다.

## 4. 판정 — **(c) 경계**

**놓친 재진입 = 진입의 11.7% · 무기한 대기 수익 델타 +6.18%p.** 판정 자(코드 상수):
놓친 비율 ≥ 20% **그리고** 수익 델타 ≥ 1%p → (a) GO · < 5% **또는** 수익 델타 < 1%p →
(b) STOP · 사이 → **(c) 경계**. 구멍이 무시할 수준은 아니나 일상도 아니고, 수익 델타도
종목에 갈려 **명백한 GO도 STOP도 아니다**.

⚠️ **이 표는 채택 근거가 아니라 크기 조사다.** 만료 구멍이 있어도 「대기 모델을 채택하라」가
아니다 — 늘어난 체결은 전부 `baseline`(닿으면 체결) 낙관 렌즈 위 값이고, 형성-예약의 진짜
이점(실체결 큐 우선순위)은 틱·호가(WAN-98, Canceled) 없이는 반쪽만 검증된다. 「엣지 없음」
(WAN-84/88/111/114/124/151)도 그대로다 — 주문 관리는 알파가 아니라 체결/자본 배분의 모양만
바꾼다.

## 5. §2/§3 — 사용자 결정 대기 (개발자 임의 착수 금지)

판정이 (c) 경계이므로 §2(형성-즉시 예약 + 가까운 주문 우선 배분)·§3(대조 측정)의 착수는
**이 크기를 알고 내리는 사용자 결정**이다(이슈 명시: 주문 생성 시점 전환 = 재-베이스라인 ·
「개발자 임의 착수 금지」). §2를 지을 경우의 선행·주의:

1. **하드 명목 가드**(PM 설계 메모 1): 실거래는 지정가가 채워지면 되돌릴 수 없으므로 총
   노출이 상한(자본×5)을 넘지 않도록 **주문 배치/취소 단계**에서 막아야 한다. WAN-180 실측상
   동시 최대 6칸·명목 스킵 6년 7건으로 드물지만 실거래는 "드물다"에 기댈 수 없다.
2. **예산 회수 시 재예약 규칙**(PM 설계 메모 2): 청산으로 예산이 비면 **유효한 존 중 현재가에서
   가장 가까운 것**을 자동 재예약(새 탭 불필요) — 이 census가 잰 구멍(재탭 실패)이 그때 같이
   닫힌다.
3. §2는 **옵트인**으로만, 안 켜면 기존 탭-생성·24봉 만료가 비트 재현(회귀 테스트).
4. §3은 켠 팔 vs 현행 팔을 같은 좌표에서 대조 — 15m은 컴퓨트가 무거우니 4h·1h부터.

**기본값·토대 불변**(측정 전용 · `ALPHABLOCK_LIVE_TRADING=false` 유지). WAN-222의 유효기간
24봉 채택은 그대로다 — §2가 채택되면 「고정 만료」 자체가 사라져 그 전제가 바뀐다(둘 중 방향
결정은 §2/§3 이후 사용자 몫).
