# WAN-252: 2h 작업 TF 승격 — DEFAULT_TIMEFRAMES에 2h 추가 (15m·1h·2h·4h)

**성격: 재-베이스라인(실행).** 사용자 결정(2026-08-05, "2h는 추가가 되어야할 것 같네" →
「작업 TF로 승격」)을 코드 기본값·문서·리포트 파급에 반영한다. **새 격자·새 수치는 없다** —
근거는 WAN-236(2h 타임프레임 성능, 9종목·6년·따뜻한 OOS) · WAN-243(2h 재진입 매칭 널)이
이미 낸 표이고, 이 이슈는 좌표 기본값 이동 + 파급 처리 + 문서다. **WAN-182가 4h를 작업
TF로 승격한 것과 같은 패턴**이다.

⚠️ **이번에 움직인 것은 엔진이 아니라 좌표다** — `ConfluenceParams()`(오프셋 2bp ·
`intrabar_live` · `unconditional` · 고정 1.5R · 롱 온리 · `combine_obs=False` · 존폭 필터
1.28)·`OrderBlockParams()`·`LeverageBookParams()`는 그대로다. 옛/새 리포트의 차이를 엔진
변화로 읽으면 안 된다.

## §1 기본값 이동 — 무엇이 어디에서 바뀌었나

| 위치 | 옛 값 | 새 값 |
| -- | -- | -- |
| `backtest/harness.py DEFAULT_TIMEFRAMES` | `("15m", "1h", "4h")` | **`("15m", "1h", "2h", "4h")`** |
| 인자 없는 `backtest.run` | 9종목 × 3TF × 못 박은 6년 | **9종목 × 4TF × 못 박은 6년** |
| `backtest.wan95_zone_limit_report` 좌표 | 9종목 × 3TF | **9종목 × 4TF**(2h 포함 재산출) |

- **`DEFAULT_TIMEFRAMES` 상수 하나가 결정 지점이다** — `backtest/run.py`가 `--tf`의 기본값을
  이 상수에서 읽고(`grid_from_args`), 채택 북 경로(WAN-213 `book_cli`)·정본 OOS(`--oos-warm`,
  WAN-166)도 같은 격자를 물려받는다. 따라서 인자 없는 실행은 이제 네 TF를 돌고, 북은
  칸=(종목,TF)이 9×4=36칸으로 는다. `--tf`를 명시하면 그대로다.
- **2h는 사전 적재가 필요 없다** — 저장된 1h 두 봉을 무손실로 합쳐 온더플라이로 파생한다
  (`OhlcvStore.load`의 `_DERIVED_TIMEFRAMES = {"2h": "1h"}`, WAN-24). 실측: 9종목 전부
  2020-07-23~2026-07-22 구간에서 26,279봉(짝수시 UTC 정렬)으로 파생된다. `ohlcv.db`에 2h
  행은 없지만 로더가 투명하게 만든다 — 이슈가 우려한 "빈/낡은 2h" 상황은 발생하지 않는다.
- **정본 리포트 = `uv run python -m backtest.run --oos-warm`**(인자 없이) — 이제 9종목 ×
  15m·1h·2h·4h × 채택 창에서 `oos_warm`(주) + `oos`(스트레스)를 병기한다.

## §2 옛 리포트 파급 — 핀 · 무변 · 재산출

WAN-182의 TF 승격(1h → 15m·1h·4h)과 **같은 결론: 파급이 예외적으로 작다.** 옛 리포트
대부분이 자기 모듈에 TF 상수를 리터럴로 들고 있거나(`DEFAULT_TIMEFRAMES = ("15m","1h")`
등) 재현 커맨드에서 `--tf`를 명시하므로, harness 기본값 이동의 영향을 받지 않는다.

| 분류 | 모듈 | 처리 | 이유 |
| -- | -- | -- | -- |
| **따라감(추적)** | `backtest/run.py` | 없음(의도) | CLI 자체 — 채택 좌표를 따라야 맞다 |
| **재산출(추적)** | `wan95_zone_limit_report` | 2h 포함 재산출 | "지금 채택된 것"을 재는 리포트는 고정하지 않는다(WAN-132/149/159/182와 같은 원칙) |
| **무변(자기 TF 상수)** | wan114/117/123_*/131/134/137/145_*/151_*/164/223/228/231/70/71/88/89 · archive/* | 없음 | `("15m","1h")` 등 자기 모듈 상수로 TF를 정의 — 기본값 이동과 무관하게 같은 행 |
| **무변(harness 읽되 명시 재현)** | wan133/142/150/152/154/197/203/204/206/209/210/211/248 | 없음 | `harness.DEFAULT_TIMEFRAMES`를 CLI 기본값으로 쓰지만 커밋된 md/csv는 재현 커맨드에서 `--tf`/`--timeframes`를 **명시**해 산출·재현한다(각 리포트의 재현 커맨드 참조). 바 실행만 축이 넓어질 뿐 결론 수치는 불변 |

- **핀(`LEGACY_TIMEFRAMES`)이 새로 필요한 모듈은 없다.** WAN-182가 TF 축에서 핀한 모듈은
  없었고(핀 대상이던 wan104/wan108은 **symbols/years** 축이었으며 WAN-216이 `archive/`로
  동결), 2h 승격도 같다. `harness.LEGACY_TIMEFRAMES`(= `("1h",)`)는 WAN-181까지의 좌표
  스냅샷이라 **손대지 않는다**(2h는 그 스냅샷과 무관).
- ⚠️ **엣지 판정 계열(WAN-84/88/111/114/124/151/201/248)은 3TF 창 기록으로 얼어붙는다** —
  좌표를 넓혀 재측정할 대상일 뿐, 2h 포함 재검은 **별도 이슈**다(개발자 임의 착수 금지 ·
  WAN-182 §4와 같은 패턴). 「엣지 없음」은 뒤집힌 게 아니다.

## §3 wan95 2h 재산출 (채택 성과)

기존 CSV(9종목 × 15m/1h/4h = 27행, 못 박은 창이라 비트 재현)는 그대로 두고 **2h 9행만**
새로 돌려 병합했다(WAN-182 재산출이 행 단위 병합한 것과 같은 방식 — 렌더는 wan95 자신의
`rows_to_frame`/`build_markdown`을 그대로 사용). `_TF_ORDER`에 2h를 넣어(1h와 4h 사이)
손익표·판단표 정렬을 고쳤다.

- **신규 3종목(DOGE·LINK·LTC) 펀딩 대리** — 이 창에서 `funding_rate` 0행이라 WAN-180/182와
  같은 규칙(기존 종목 중 확정 펀딩 평균 최고 = 롱에게 가장 비싼 종목의 시계열)으로 보정한다
  (`apply_funding_proxy`). 자기 데이터가 생기면(WAN-178 백필) 저절로 꺼진다.
- ⚠️ **옛 판(3TF)과 셀 비교 금지가 아니라 — 2h는 새로 추가된 행이다.** 15m/1h/4h 행은
  좌표가 같아 비트 재현되므로, 이 재산출은 기존 표에 2h 9행을 얹은 것이다.
- 🚨 전부 `baseline`(낙관) 렌즈 위의 값이고 IS/OOS 분해가 아니다(그쪽 정본은 WAN-176/236 표).

## §4 범위 밖 · 불변

- **수집 TF 불변** — `config.settings._default_timeframes()`(수집 대상)는 `1m·5m·15m·1h·4h·1d`
  그대로다. 2h는 파생(온더플라이)이라 저장 대상이 아니다(수집하면 1h와 중복 저장).
- **라이브 감시 TF 불변** — `_default_live_signal_timeframes()`는 WAN-191의 15m·1h·4h
  그대로다(하드코딩, `DEFAULT_TIMEFRAMES`와 독립). 2h 승격은 **측정·백테스트 축**을 넓힌
  것이지 페이퍼 감시 대상 확대가 아니다 — 감시 확대는 WAN-191 부류의 별도 사용자 결정이다.
- **1d 제외 유지**(표본 미달, WAN-182). **엔진 토대·실거래 보류 불변**
  (`ALPHABLOCK_LIVE_TRADING=false`).
- ⚠️ **인자 없는 실행이 더 무거워진다** — 27셀(9×3TF) → 36셀(9×4TF). 탐색 중엔 심볼·TF를
  좁혀 돌 것.

## §5 회귀 테스트 (`tests/test_wan252_rebaseline.py`)

라벨이 아니라 **동작**으로 고정한다:

- 인자 없는 CLI가 실제로 15m·1h·2h·4h 네 축을 돈다(파서 산출물) · `--tf` 명시가 이긴다.
- 2h가 저장 행 없이 1h에서 파생되고 짝수시 정렬·2h 배수 간격이다(사전 적재 불필요).
- wan95 `_TF_ORDER`가 2h를 1h와 4h 사이에 놓는다(누락 시 정렬이 NaN으로 깨진다).
- 범위 밖 불변: 수집 TF에 2h 없음 · 라이브 감시 TF는 15m·1h·4h 그대로.
- `tests/test_wan182_rebaseline.py`의 채택 좌표·바-CLI 단언을 4축으로 갱신(WAN-182 창·
  심볼 단언은 불변).
