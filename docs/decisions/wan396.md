# WAN-396 — 비용 분해가 붙지도 않은 진입 슬리피지 5bp를 계상했다

**버그 수정 ＋ 공개 표 정정.** 판정은 **(가) 분해만 틀렸다** — `net R`은 처음부터 맞았고
`gross`·`slippage`·`cost`만 같은 크기로 부풀어 있었다. **엔진·전략·기본값·토대는 하나도 안
건드렸다**(`ConfluenceParams()`·`LeverageBookParams()` 그대로 · 새 격자 없음 ·
`ALPHABLOCK_LIVE_TRADING=false` 유지).

재현:

```
uv run python -m backtest.wan396_entry_slippage_correction
uv run pytest tests/test_wan396_entry_liquidity.py -q
```

## §1 판정 — (가), 그리고 그 근거는 코드다

> **한 문장**: 백테스트 엔진은 진입 체결가에 슬리피지를 **붙이지 않았고**(후보의
> `entry_liquidity`가 기본 **메이커**), 비용 분해만 `BacktestConfig.entry_liquidity`(기본
> **테이커**)를 읽어 5bp가 붙었다고 **역산**했다 — 그래서 손익은 맞고 진단만 틀렸다.

| | 파일 | 읽는 값 | 기본값 | 결과 |
| -- | -- | -- | -- | -- |
| **엔진** | `backtest/zone_limit_backtest.py::_to_trade` | `cand.entry_liquidity` | **MAKER** | `entry_fill == entry_price` (슬리피지 0) |
| **분해(옛)** | `backtest/wan370_cost_decomposition.py::decompose_trade` | `cfg.entry_liquidity` | **TAKER** | `entry_ref = entry_price/(1+5bp)`로 되돌림 |

🚨 **왜 `net R`로는 안 보였나** — 분해는 진입 참조가를 밀어 되돌리는 구조라 그 밀린 만큼이
`gross`에도 `slippage`에도 **똑같이** 더해진다. `net = gross − 비용`이라 **정확히 상쇄된다.**
「라벨과 동작이 어긋남」(WAN-91/95/112/123/159/194)의 **회계 축 변종**이고, WAN-393이
*「R이라 불리는 자가 셋」*으로 못 박은 것과 같은 부류다.

📌 **왜 5년 동안 테스트가 못 잡았나** — `tests/test_wan370_cost_decomposition.py`의 픽스처가
`BacktestConfig(entry_liquidity=Liquidity.MAKER)`를 **명시**해 설정과 엔진을 우연히 맞춰
놨다. 프로덕션(`harness.build_config`)은 그 필드를 **아무 데도 안 넘긴다** — 즉 테스트는
버그가 없는 세계를 돌고 있었다. 새 테스트는 반대로 **프로덕션 기본값(테이커)을 일부러
집어넣고** 진입 슬리피지가 0인지 본다.

## §2 고친 것 — 진입 유동성의 단일 소스는 「거래」다

1. **`Trade.entry_liquidity`(신설, 기본 `MAKER`)** — 엔진이 체결가·수수료를 만들 때 실제로 쓴
   값을 거래가 들고 나간다(`_to_trade`가 `cand.entry_liquidity`를 그대로 싣는다). **순수
   기록이라 손익에 안 쓰이고**, 기본값이 `_Candidate.entry_liquidity`와 같아 **비트 재현**이다.
2. **분해가 `trade.entry_liquidity`를 읽는다** — 청산 쪽이 `cfg.exit_liquidity` 한 곳에
   물어보는 것과 같은 규칙의 진입 판이다. 여기서 다시 정하면 엔진과 리포트가 또 갈라진다.
3. **`BacktestConfig.entry_liquidity`는 사문화됐다** — A안이 제거된 뒤(WAN-200/215) 이 필드를
   읽는 프로덕션 코드가 **하나도 없다**. 🚨 **기본값을 뒤집지 않았다**(이슈 §4-2 경고) —
   `config_json` 실행 지문(WAN-106)에 실려 있어 바꾸면 적재된 실행의 `run_id`가 통째로
   달라진다. 대신 독스트링이 「읽지 마십시오」를 적고 **배선 가드**가 지킨다.

### 회귀 테스트 — 라벨이 아니라 동작으로 (완료기준 2)

`tests/test_wan396_entry_liquidity.py` 20개. 핵심은 **`gross`와 `slippage`를 각각** 보는 것이다
(상쇄되므로 `net`만 보면 통과한다):

* 메이커 진입이면 `entry_fill == 지정가` · 테이커면 실제로 밀린다(**반증** — 앞 테스트가 공허하지 않다).
* 설정이 테이커여도 메이커 진입 거래의 분해 `slippage == 0`이고 `gross`가 **순수 가격 이동**과 같다.
* 같은 거래를 `cfg.entry_liquidity`만 바꿔 분해하면 **모든 성분이 같다**(사문화 확인).
* **배선 가드** — `backtest/`·`live/`·`paper/`·`qc/` 어느 모듈도 설정 객체에서 `.entry_liquidity`를
  읽지 않는다(AST). 가드 자체가 옛 코드 모양을 실제로 잡는지도 함께 고정한다.
* **함정이 아직 거기 있다**는 기록 — `harness.build_config("1h").entry_liquidity is TAKER`인데
  그 실행의 거래는 `MAKER`다. 그래서 가드가 필요하다.

## §3 공개 표 정정 — 격자를 다시 안 돌리고 **열만** 되계산했다

거래 단위 산출물이 저장돼 있지 않지만, **보정이 근사가 아니라 항등식**이라 다시 돌릴 필요가 없다.
옛 분해의 허수 진입 슬리피지는

```
phantom_i = entry_notional_i × slip/(1+slip) = entry_fee_i × K,   K = (slip/(1+slip)) / maker_rate
```

이고 `entry_fee_i = entry_notional_i × maker_rate`라 **K가 거래에 무관한 상수**다(채택 요율에서
`K = 2.4987506…`). 평균도 선형이므로 R 단위 집계 열에 그대로 적용된다:

```
보정 gross_r / slippage_r / cost_r  =  각각 − K × entry_fee_r        ·  net_r 은 불변
```

도구: `backtest/wan396_entry_slippage_correction.py` → 대조표
[`backtest/reports/wan396_entry_slippage_correction.csv`](../../backtest/reports/wan396_entry_slippage_correction.csv) ·
[`.md`](../../backtest/reports/wan396_entry_slippage_correction.md). **원본 여섯 CSV는 그때의
기록으로 보존한다**(WAN-194/297/325 관행) — 덮어쓰지 않고 전후를 한 표에 낸다. 보정한 행 **346개**.

### 헤드라인 (`oos_warm`)

| 표 | 행 | gross 전 → **후** | slippage 전 → **후** | cost 전 → **후** | net(불변) |
| -- | -- | --: | --: | --: | --: |
| wan370 | `maker_tp`(채택, 필터 켬) | +0.0920 → **+0.0071** | 0.1350 → **0.0501** | 0.2229 → **0.1380** | −0.1309 |
| wan370 | `taker_tp`(전) | +0.0918 → **+0.0069** | 0.1698 → **0.0849** | 0.2716 → **0.1867** | −0.1798 |
| wan388/389/394 | 채택 좌표(필터 끔) | +0.0765 → **+0.0019** | 0.1186 → **0.0440** | 0.1960 → **0.1213** | −0.1194 |

### 검산 셋

* **(a) 슬리피지 항등식** — `slippage_r == K×entry_fee_r + Kx×(테이커 청산 수수료)`가 **346행
  전부에서 최대 잔차 `3.2e-14`**(기계 정밀도). 이것이 「진입 몫이 정확히 `K×entry_fee_r`」의
  근거다. 🚨 설명되지 않는 행이 하나라도 있으면 도구가 **죽는다**(조용히 보정하지 않는다).
* **(b) 독립 자 대조** — `gross_r − slippage_r == mean_gross_r_after_slippage`(잔차 `4.9e-14`).
  그 열은 `realized_pnl + 수수료`로만 만들어 **이 버그에 안 걸린다** — 보정이 두 열에서 같은
  값을 빼므로 그 차가 **불변**이고, 신뢰할 수 있는 양을 안 건드렸다는 직접 증거다.
* **(c) `net_r` 불변** — 보정 대상 열에 아예 없다(판정 (가)의 정의).

## §4 WAN-370 §1 판정 재확인 (완료기준 4)

[`wan370.md`](wan370.md) 맨 위에 **정정 배너**를 달았다. 요지:

* **판정 문자는 (나)로 남지만 폭이 무너진다** — 채택 팔 gross가 노이즈선(±0.005R)의 **18배 →
  1.4배**다. 그리고 **존폭 필터를 끈 오늘 좌표**(WAN-384 이후 = WAN-388/389/394가 도는 좌표)에서는
  **+0.0019R로 「(0 근처) 시장에서도 본전」**으로 넘어간다. 판정을 가르는 것이 이제 **좌표**다.
* 🚨 **「비용을 전부 0으로 만들어도 천장이 +0.09R」은 자릿수가 틀렸다** — 천장은 **+0.007R**
  (필터 끔 **+0.002R**)이다. WAN-378/388/389/394/395가 그 문장을 인용했다.
* 🚨 **「최대 비용은 슬리피지(62%)」도 틀렸다** — 보정 후 **36.3%**이고, 남은 슬리피지는 **전부
  손절·만료 청산의 몫**이다. 비중 순서: 슬리피지 36.3% · 손절 수수료 29.1% · **진입 수수료
  24.6%** · 익절 수수료 10.1%.
* 📌 **TF 분해가 더 많이 말한다** — 보정 후 `oos_warm` gross는 15m **+0.0221R** · 2h +0.0021R ·
  1h **−0.0179R** · 4h **−0.0764R**이라 *「시장에서는 이기고 있었다」*의 실체는 **15m 하나**다.
  하필 15m이 낙관 체결 의존이 가장 깊은 축이다(WAN-124/330/348).
* ⚠️ **§2(익절 메이커 전환) 결정은 안 흔들린다** — 전환의 몫 **+0.0489R**은 두 팔의 `net R`
  차이이고 `net R`은 이 버그에 안 걸린다.

## §5 범위 밖 · 경고

* ❌ **슬리피지 요율(5bp) 자체는 안 건드렸다** — WAN-397 소관이다. 이 이슈는 *「5bp가 엉뚱한 데
  붙는다」*만 다룬다. 두 질문을 섞으면 「분해를 고쳤더니 좋아졌다」와 「요율을 바꿨더니 나빠졌다」를
  못 가른다. 📌 **다만 WAN-397에 주는 입력이 하나 생겼다** — 보정 후 남은 슬리피지는 **전부
  청산 쪽**이라, 요율 현실화의 영향은 진입이 아니라 **손절·만료 청산**에 걸린다.
* ❌ **기본값·토대 전환 없음** · 전략 규칙 불변 · 새 격자 없음 · 원본 CSV 무수정.
* 🚨 **「gross가 사실 0이었다」를 「엣지 없음」의 새 근거로 인용 금지** — 고친 것은 **회계 한
  줄**이고 「엣지 없음」(WAN-84/88/111/114/124/151/201/248/386)은 *진입 규칙이 무작위와
  구분되는가*라는 **다른 질문**이다. 반대로 「그래서 비용만 줄이면 된다」도 아니다 — 보정은
  천장을 **낮췄지** 높이지 않았다.
* ⚠️ **페이퍼 쪽 같은 축은 WAN-371**(페이퍼가 진입을 **실제로** 테이커로 계산했다). 그쪽은
  *「안 문 것을 물었다」*가 아니라 *「물지 않아야 할 것을 물었다」*라 **다른 이슈**지만, 둘 다
  `entry_liquidity`가 두 곳에 살아서 생겼다.
* ⚠️ **캐시가 통째로 미스된다** — `backtest/models.py`·`backtest/zone_limit_backtest.py`가
  엔진 소스라 후보 payload 캐시(WAN-394 §0)와 야간 타임라인 캐시(WAN-297/325)의 리비전이
  바뀐다. **수치는 하나도 안 바뀌는데도 그렇고, 그게 맞는 동작이다**(WAN-253 규약 — 「엔진을
  한 글자만 고쳐도 전 칸 미스」). 되채우기 절차는
  [`docs/ops/wan239-nightly-timeline-cache.md`](../ops/wan239-nightly-timeline-cache.md).
