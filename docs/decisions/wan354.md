# WAN-354 — 백테 병렬 워커 수가 서버에서 실제로 먹게 한다

**결론 한 줄**: 이슈의 전제가 절반 틀렸다 — 야간 크론은 **4-way 오버서브가 아니라 직렬**로
돌고 있었다. `alphablock` CLI의 백테 하위 명령이 `--jobs` 기본값을 **리터럴 1로 박아** 둬서
`ALPHABLOCK_BACKTEST_JOBS`가 그 경로에 **닿지도 않았기** 때문이다. 「덮어쓰기 자리가 안
쓰였다」 한 겹 아래에 **「그 자리가 이 경로에는 배선조차 안 돼 있었다」** 가 있었다.
이 PR은 그 배선을 잇고, `.env`가 새던 구멍을 막고, 서버에서 **동작으로** 확인할 도구와
런북 절차를 싣는다. **코드 기본값(4)은 안 바꿨다**(완료 기준 4).

- 도구: `scripts/wan354-server-jobs-check.sh`(읽기 전용 점검) · `scripts/wan354_jobs_probe.py`
  (워커가 정말 몇 개 뜨는지)
- 런북: [`docs/ops/server-migration.md`](../ops/server-migration.md) §2a ·
  [`docs/ops/wan239-nightly-timeline-cache.md`](../ops/wan239-nightly-timeline-cache.md)

⚠️ **측정값·재현성·캐시 지문은 하나도 안 움직인다** — `--jobs`는 결과를 안 바꾸는 순수
성능 노브다(WAN-121: 직렬 = 병렬 비트 동일). 옛 표 재산출도 캐시 되채우기도 **불필요**하다.
**엔진·전략·기본값·토대 불변**(`ConfluenceParams()`·`LeverageBookParams()` 그대로) ·
DB에 아무것도 쓰지 않는다(WAN-194) · 실거래 보류 유지(`ALPHABLOCK_LIVE_TRADING=false`).

## §1 — 설정이 어디서 오는가 (확인. 지어내지 않았다)

이슈가 「`Settings`가 `.env`를 실제로 읽는지 PM이 확인하지 못했다」로 남긴 자리다. 로컬에서
**새 프로세스를 띄워** 실측했다(회귀 테스트가 같은 방식으로 고정한다 —
`tests/test_wan354_backtest_jobs_wiring.py`).

| 물음 | 답 | 근거 |
| -- | -- | -- |
| `.env`를 읽나 | ✅ 읽는다 | `SettingsConfigDict(env_file=..., env_prefix="ALPHABLOCK_")` |
| 어디 기준으로 찾나 | 🚨 **CWD 기준 상대 경로**였다 | `cd /tmp` → `backtest_jobs` **4**(= 코드 기본값), `.env`가 있는 디렉터리에서는 그 값 |
| 실제 환경변수와의 우선순위 | 환경변수가 이긴다 | `ALPHABLOCK_BACKTEST_JOBS=7` → 7 |
| systemd 유닛은? | `WorkingDirectory=<저장소>`라 그 `.env`를 읽는다 | 유닛 템플릿 9개 전부 |
| 크론은? | 줄이 `cd <저장소>`를 하므로 읽는다 | 사용자 crontab 실측 |
| **CLI가 그 값을 쓰나** | 🚨 **아니다** | `cli/main.py`의 `trades`·`compare`·`stop-width`·`parity`가 `--jobs` **`default=1`** 리터럴 |

📌 **그래서 §2 는 이슈 표대로 하지 않았다.** 이슈는 세 경로에 각각 값을 주입하라고 했지만
(크론 줄 · systemd `Environment=` · `.env`), §1 이 밝힌 사실은 **`.env` 한 자리가 이미 세
경로를 전부 덮는다**는 것이다. 같은 값을 세 곳에 두면 갈라진다 — 그리고 이 저장소가 반복해
겪은 사고가 정확히 그 「두 자리가 다른 값을 든」 상태다(WAN-91/95/112/123/159).

## §2 — 고친 것

### (a) 🚨 CLI가 설정을 읽게 했다 — 이 이슈의 본문

`alphablock`의 백테를 부르는 네 하위 명령(`trades`·`compare`·`stop-width`·`parity`)이
`--jobs` 기본값을 **1로 박아** 두고 있었다. 함의가 둘이다:

1. **야간 크론은 오버서브가 아니라 직렬로 돌았다.** 이슈 제목의 「2코어 박스에서 4-way
   오버서브」는 이 경로에 대해서는 **사실이 아니다**. (WAN-322/324의 서버 실측 6분 23초도
   직렬 값이고, 그 실행의 `user`가 2분 13초뿐이라 **병목은 CPU가 아니라 디스크**였다.)
2. **`.env`에 값을 넣어도 그 경로에서는 아무 일도 일어나지 않았을 것이다.** 이슈가 요구한
   「세 경로 전부」는 배선 없이는 **원리적으로 달성 불가능**했다.

이제 미지정이면 `harness.default_jobs()`(= `ALPHABLOCK_BACKTEST_JOBS`)로 풀고, 명시적
`--jobs N`은 그대로 이긴다 — `backtest.run`의 `jobs_from_arg`와 **같은 규약**이다. 푸는
자리는 `cli.main.main()` **한 곳**이다(하위 명령마다 각자 풀면 「하나는 설정을 읽고 하나는
리터럴」인 지금 상태가 다시 만들어진다).

⚠️ **알고 받는 변화**: 서버 야간 크론이 **직렬 → 설정값(권고 2)** 이 된다. 코어 수와 같으니
오버서브는 아니지만 러너·수집기와 나눠 쓰는 자원이 늘긴 한다. 메모리가 빠듯하면
`ALPHABLOCK_BACKTEST_JOBS=1`로 되돌리면 옛 동작과 **정확히 같다** — 그게 노브의 용도다.

⚠️ **대시보드 화면 버튼은 여기 오지 않는다** — 거기는 의도적으로 직렬(`jobs=1`)이다
(워커마다 120일치 1분봉 사본을 들어 `BrokenProcessPool`이 났다, WAN-324). 손대지 않았다.

### (b) `.env`가 저장소 밖에서 조용히 무시되던 구멍을 막았다

`env_file=".env"`(CWD 상대) → `env_file=(<저장소 루트>/".env", ".env")`. 뒤쪽이 이기므로
**CWD의 `.env`는 여전히 최우선**이고 저장소 루트 판은 그것이 없을 때만 쓰인다 — 기존 동작을
바꾸지 않는 **순수 추가**다. 오늘 서버가 맞는 것은 크론이 `cd`를 하고 유닛이
`WorkingDirectory`를 두기 **때문**이지 설계 덕이 아니었고, 그 우연이 깨지는 순간이 곧
「설정했다고 믿으면서 기본값으로 도는」 상태다.

### (c) 실제로 쓴 워커 수를 남긴다 — 라벨이 아니라 동작 (완료 기준 2)

- `alphablock` CLI: 첫 줄에 `병렬 설정: 워커 N개 (--jobs 미지정 → 설정 ALPHABLOCK_BACKTEST_JOBS=N)`
  를 **stderr**로 찍는다(stdout은 표/CSV 전용). 야간 크론 로그에서 사후 확인이 된다.
- `backtest.run` 격자: **실제로 풀에 넘어간** 워커 수를 찍는다(요청값이 아니라 셀 수로 캡된
  값 — `--jobs 4`인데 셀이 1개면 `워커 1개 (1셀)`).
- `scripts/wan354_jobs_probe.py`: `ProcessPoolExecutor`를 실제로 띄워 **자식 프로세스 수**를
  센다. 설정 파일에 줄이 있는지가 아니라 프로세스가 그 수만큼 생기는지를 본다.
- `scripts/wan354-server-jobs-check.sh`: 위를 포함한 읽기 전용 점검(코어 수 · `.env` ·
  두 CWD에서 푼 값 · 크론 줄 · 유닛의 `WorkingDirectory`/`Environment` · 워커 실측).

📌 **WAN-121 불변은 지켰다** — 「`--jobs`가 결과·로그를 안 바꾼다」는 테스트가 이제
**그 한 줄만 빼고** 비교한다. 그 줄이 재는 것은 계산이 아니라 노브 자체다.

### (d) 안 한 것과 그 이유

| 이슈가 말한 것 | 안 한 이유 |
| -- | -- |
| systemd 유닛에 `Environment=`/`EnvironmentFile=` | 유닛은 `WorkingDirectory=<저장소>`라 이미 그 `.env`를 읽는다. 같은 값을 두 자리에 두면 갈라지고, `.env`에는 API 키·텔레그램 토큰이 있어 `systemctl show`로 새어 나온다 |
| 크론 줄에 환경변수 주입 | `.env` 한 자리가 세 경로를 덮는다. 크론 줄에만 넣는 것이 바로 이슈가 경고한 「한 곳만 고치기」다 |
| 코드 기본값 4 → 2 | 완료 기준 4 — 개발 머신(M1) 기준값이라 그대로 둔다 |
| §4 실측(`user`/`real`) | **서버 몫이다** — 이 세션에 SSH가 없다(WAN-195/314와 같은 제약). 다른 머신 값을 옮겨 적지 않는다 |

## §3 — 남은 것 (사람이 서버에서 1회)

```bash
cd ~/AlphaBlock && git pull && uv sync
nproc                                              # 2
echo 'ALPHABLOCK_BACKTEST_JOBS=2' >> .env          # 이 한 줄이 세 경로를 덮는다
./scripts/wan354-server-jobs-check.sh -o /tmp/wan354.md   # 라벨이 아니라 동작으로 확인
```

- ⚠️ **유닛 템플릿은 안 건드렸으므로 `install-systemd.sh` 재실행은 불필요**하다(WAN-318 §7은
  템플릿을 고쳤을 때의 절차다).
- §4(전환 전후 `user`/`real` 분해)는 **선택**이고 서버 몫이다. 🚨 벽시계만 보지 말 것 —
  같은 머신의 다른 작업과 경합해 출렁인다(WAN-324 규약). 🚨 다른 모듈·다른 머신 값을 옮겨
  적지 말 것.
