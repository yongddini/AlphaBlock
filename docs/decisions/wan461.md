# WAN-461 — 수집기 연결 하나가 조용히 먹통이 되면 감지해서 다시 붙기

운영/수집기 수정이다. 전략·엔진·기본값·토대 불변, 실거래 보류 유지(`ALPHABLOCK_LIVE_TRADING=false`).

## 사고 (2026-10-20 05:20 KST~)

연결 두 개 중 **연결 2/2만** 136분 동안 1분봉을 하나도 남기지 못했다(QNT~ZEC 11종목). 연결 1/2는
계속 저장했고, 로그에는 10-19 09:41 따라잡기 이후 끊김·재접속·에러가 **한 줄도 없다**.

## 왜 기존 감시가 안 걸렸나 — 원인 판정(코드 논증 · 서버 로그 대조 전)

연결마다 따로 걸린 유휴 감시(`guard_idle`, WAN-173 · 90초)는 이미 있었다. 136분 동안 안 걸렸다면:

| 후보 | 판정 |
| -- | -- |
| ① 서버 코드가 옛것(WAN-456 이전) | **가능성 낮음** — WAN-456 머지 09:21 · 프로세스 기동 09:30 |
| ② 메시지는 오는데 봉이 저장 안 됨 | **가장 정합적** — 이벤트 루프는 살아 있었고(연결 1/2 저장), 90초 무수신이면 유휴 감시가 반드시 걸리며, half-open TCP라면 websockets 핑(20s+20s)이 닫아 WAN-456 경로가 로그를 남겼을 것이다. **그 연결로 무언가는 계속 들어왔다**고 읽는 것이 남은 설명이다 |
| ③ 감시 경로 버그(예외 삼킴) | 테스트로 배제 — 2연결 중 하나만 무수신이면 제한 시간 안에 `StreamStalled`가 올라와 재접속한다(`tests/test_wan461_silent_connection.py`) |

⚠️ ②는 **확정이 아니다** — 서버 로그(`collector-stall-*.log`)에 `StreamStalled`·「유휴」 줄이 있었다면
①/③ 쪽이다. 그래서 이번 수정은 ②를 잡는 동시에, 다음에 걸리면 **답을 남기게** 했다.

## 바꾼 것

1. **「저장 없음」 감시**(`StreamNoProgress`, `consume_messages(progress_timeout_seconds=)`) — 연결마다
   「가장 짧은 TF + 여유(기본 120초)」 동안 메시지만 오고 확정봉 저장이 0건이면 그 연결을 멎은 것으로
   본다(1분봉 연결 = 180초). 판정은 메시지가 올 때만 하므로 타이머 태스크가 없고, 메시지가 아예 안 오면
   유휴 감시가 먼저 걸린다 — **둘을 합쳐야 「그 연결이 일을 하나」가 닫힌다.** 걸리면 정지 직전 마지막
   메시지(앞 300자)를 경고 로그에 남긴다(②의 정체 확인용).
2. **어느 연결인지 밝힌다** — `StreamStalled.tag_connection`이 「연결 N/M」을 싣고, 경고 로그 · 복구
   텔레그램 한 줄에 그대로 나온다(`연결 2/2: 웹소켓 유휴 90s 초과 무수신 … → 재접속`). 알림은 평문
   (WAN-321). 기존 경로 그대로 **전 연결을 닫고 다시 붙고**(WAN-456) 접속 직후 꼬리 따라잡기(WAN-314)가
   빠진 봉을 메운다.
3. **덤 — 연속 재접속 카운터 리셋** — `run_with_recovery`가 프로세스 수명 내내 누적해(「#5 → 16초」)
   며칠 정상으로 돈 뒤 한 번 멎어도 긴 백오프로 시작했다. 이제 직전 접속이 `healthy_after_seconds`
   (기본 120초) 넘게 버텼으면 #1 · 1초로 돌아간다. `max_reconnects`(테스트용)는 누적 그대로.

새 설정(`.env.example`에 예시): `ALPHABLOCK_COLLECTOR_STREAM_PROGRESS_GRACE_SECONDS=120.0` ·
`ALPHABLOCK_COLLECTOR_RECONNECT_HEALTHY_AFTER_SECONDS=120.0`.

## 알고 받는 한계

* 판정 단위는 **연결**이다 — 한 연결 안의 일부 종목만 멎고 나머지가 계속 저장되면 이 감시로는 안 보인다
  (그 경우는 Health 워치의 시리즈별 신선도 경고가 남는 방어선이다).
* 거래가 없는 1분에 바이낸스가 확정봉을 안 보내는 종목만 한 연결에 담기면 오탐(재접속 1회 + 따라잡기)이
  날 수 있다. 지금 구성(연결당 수십 종목 × 1분봉)에서는 사실상 없고, 비용도 재접속 한 번이다.
* 완료 기준 3(「배포 후 1주일 동안 2.5시간 이상 지연 없음」)은 **배포 후 관찰 항목**이라 이 PR로 닫히지
  않는다.
