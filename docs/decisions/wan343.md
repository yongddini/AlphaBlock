# WAN-343 — 같은 봉을 주는데 라이브와 백테가 다른 존 목록을 낸다

**성격**: 측정·진단 도구 + 가설 기각 두 건. **엔진·전략·기본값·토대 불변**
(`ConfluenceParams()`·`LeverageBookParams()` 그대로) · **DB에 아무것도 쓰지 않는다**(WAN-194) ·
실거래 보류 유지(`ALPHABLOCK_LIVE_TRADING=false`).

---

## 0. 이 이슈가 답해야 하는 질문

WAN-342 서버 실측이 짝 없는 셋업을 조인 키 조각으로 갈랐고 **`(a) 존 없음`이 두 날 모두
13/17(76.5%)** 였다. 그런데 `(a)`는 **관찰**(「같은 칸의 백테 **셋업 행**에 그 존 시작이
없다」)이지 **원인**이 아니다. 셋업 행이 없는 이유는 최소 넷이고 **후속이 서로 완전히
다르다**:

| 갈래 | 뜻 | 후속 |
| -- | -- | -- |
| **창 밖** | 백테 탐지 창(워밍업)보다 이른 존 | 대조 도구의 근사(`--warmup-days`) |
| **존 미탐지** | 창 안인데 백테가 그 존을 만든 적이 없다 | **엔진 파리티 결함** |
| **무효화 선행** | 백테가 라이브 탭 전에 그 존을 죽였다 | **문서화된 근사**(아래 §3) |
| **탭 기록 없음** | 존은 양쪽에 있는데 그 봉의 탭이 백테에 없다 | 탭 판정 축 |

**가르지 않으면 알려진 근사를 결함으로, 결함을 근사로 읽는다.** 이 이슈는 그 자를 만들고,
그 위에서 후보 가설 두 개를 실측으로 기각했다.

## 1. §1 — 라이브 운영 이벤트 가설: **기각**(이 이슈 첫 코멘트, 서버 2026-08-20)

시각 클러스터 셋을 `live_runner_sessions`와 대조한 결과:

| 클러스터 | 그때 세션 | 판정 |
| -- | -- | -- |
| 08-17 `06:31~06:40` (8건) | 세션 42 한가운데 | ❌ 재시작 없음 |
| 08-18 `00:12~01:00` (7건 · 전부 TRX) | 세션 44 한가운데 | ❌ 재시작 없음 |
| 08-18 `10:04~10:53` (6건) | 세션 45 종료 `10:03:06` → 46 시작 `10:04:20` | 🚨 겹침(첫 항목 1건) |

**앞의 두 클러스터 15건이 세션 한가운데**라 재시작·따라잡기(WAN-306)로는 짝 없음의 대부분을

📌 **부수로 나온 「3.5일에 재시작 10회」는 WAN-344로 빠졌다** — 결론을 섞지 말 것(그쪽은
재시작이 **정상**이었고 진짜 발견은 「러너 정지 감시가 아무 데도 등록돼 있지 않다」였다).

## 2. §2-3 — 탐지 컨텍스트 창 가설: **기각**(로컬 실측 2026-08-21)

이슈 §2-3이 남긴 후보다. 두 창은 실제로 크게 다르고 **TF마다 방향까지 반대**다:

| TF | 라이브 창(`live_signal_lookback_bars=1500`봉) | 백테 창(`DEFAULT_WARMUP_DAYS=120`일) | 어느 쪽이 기나 |
| -- | --: | --: | -- |
| 15m | 1,500봉 = **15.6일** | 11,520봉 = 120일 | 백테가 **7.7배** |
| 1h | 1,500봉 = **62.5일** | 2,880봉 = 120일 | 백테가 1.9배 |
| 2h | 1,500봉 = **125일** | 1,440봉 = 120일 | 사실상 같다 |
| 4h | 1,500봉 = **250일** | 720봉 = 120일 | **라이브가 3.5배** |

「창이 다르니 탐지도 다를 것」은 그럴듯했다. **실측은 반대다.**

같은 종목·같은 봉을 두 창으로 각각 탐지해 **두 창이 함께 보는 구간**의 존을 대조했다
(6종목 × 15m·1h·4h = 18칸, 로컬 `data/ohlcv.db`):

```
공통구간 존 총 666개 · 불일치 6개 (0.90%)
```

📌 **그리고 그 6개는 전부 창 시작 근처다** — 경계 +5·+5·+7·+8·+11·+25봉이고, 어느 것도 창
끝에서 713봉 안쪽으로 들어오지 못한다. 탐지기가 스윙 피벗을 세우는 데 앞선 봉이 필요한
**워밍업 경계 효과**이지 전역 차이가 아니다.

🚨 **정체성만 같은 게 아니라 생애까지 같다** — 공통 구간에서 함께 잡힌 존의
`break_time`·`swept_time`·`tapped_times` **불일치 0건**. 즉 창 길이는 그 구간의 존을 만들지도
지우지도, **더 일찍/늦게 죽이지도** 않는다.

**따라서 §2-3은 `(a) 존 없음`을 만들지 못한다** — 관찰된 셋업의 존은 최고령 17일(WAN-337)로
두 창 깊숙이 들어와 있다. 회귀는 `tests/test_zone_detection_window.py`가 동작으로 막는다
(이 검사가 죽으면 「라이브와 백테가 같은 엔진」이라는 파리티 전제 자체가 흔들린다).

⚠️ **「창 차이가 아무 데도 안 나타난다」는 뜻은 아니다** — 창 **밖** 존은 당연히 한쪽에만
있다(4h는 라이브가 130일 더 본다). 그건 창 길이의 정의이지 탐지 차이가 아니고, 새 도구가
`창 밖` 사유로 **따로 센다**.

⚠️ **로컬 데이터는 08-17·08-18을 덮지 못한다**(상위TF가 2026-08-14에서 멈춘다) — 이 §2는
**메커니즘**을 잰 것이지 그 두 날의 표가 아니다.

## 3. §2-1(무효화 시점)은 이미 코드가 자백해 둔 자리다

`live.limit_engine.on_htf_bars`가 이렇게 적어 뒀다:

> 백테스트는 `break_time`(무효화 봉 시작)에 취소하지만 라이브는 그 봉이 닫혀 탐지가 확인된
> 지금이다 — **한 봉 늦는 알려진 근사**

즉 존이 봉 `B`에서 무효화되면 백테는 `B` 시작에 죽이는데 라이브는 `B`가 닫혀야 안다. 그
사이에 라이브가 탭·체결하면 **백테에는 없는 셋업**이 생긴다 — 정확히 `(a)`로 보인다.
📌 이 갈래의 **직접 서명은 「무효화 봉 = 라이브 탭 봉」**이고, 새 도구가 그 건수를 따로 센다.

⚠️ **가설이지 판정이 아니다** — 그 두 날의 존 대장을 봐야 결정된다(§5).

## 4. 무엇을 실었나 — `--zone-audit`

`alphablock stop-width --day … --with-backtest --zone-audit`

* `live/zone_facts.py` — `ZoneFact`·`CellZoneFacts`(존 대장의 감사용 축약 + **실측 탐지 창**).
  잎 모듈인 이유는 순환 임포트를 피하기 위해서다.
* `live/zone_audit.py` — 순수 함수. 짝 없는 **라이브** 셋업을 그 칸의 존 대장과 대조해
  «창 밖 / 존 미탐지 / 확정 시각 / 무효화 선행 / 소멸 선행 / 탭 기록 없음 / 설명 안 됨»으로
  가르고, 사유별 집계 + 판정 한 줄을 낸다.
* `live/trade_timeline.py` — `backtest_zone_facts_by_cells()`. 셋업 행이 소비하는 **그**
  `OrderBlockResult`에서 대장을 뽑는다(다른 탐지를 다시 돌리지 않는다).
* `live/stop_width_parity.py` — `unpaired_live_cells()` + `attach_zone_audit()`. **덧붙이기**라
  짝·인구조사·귀속 분류가 하나도 안 바뀐다.

### 설계에서 지킨 것

* 📌 **다시 분류하지 않는다** — `attribute_unpaired`가 낸 그 행을 그대로 감사한다. 두 벌로
  갈라지면 같은 셋업이 두 블록에서 다른 부류를 얻는다(WAN-333/335 규약).
* 📌 **감사할 칸만 굽는다** — 짝 없는 라이브 셋업이 있는 칸만. 채택 좌표 48칸을 다 구우면
  하루치 6분+다(WAN-322). **몇 칸을 굽는지 먼저 찍는다**(WAN-335 §1-3 규약).
* 🚨 **캐시가 이 계층을 대신하지 못한다** — 야간 캐시에 담기는 것은 셋업 **행**이지 존
  대장이 아니다. 그래서 감사는 그 칸을 다시 굽고, 화면이 그 사실을 밝힌다.
* 🚨 **판정 순서가 곧 우선순위다**(창 → 탐지 → 확정 → 무효화/소멸 → 탭 → 설명 안 됨) — 창 밖
  존의 「무효화 시각」은 존재하지 않는다.
* 🚨 **대장을 못 받은 칸을 「존이 하나도 없다 = 미탐지」로 읽지 않는다** — `대상 아님`이다.
  빈 대장을 미탐지로 세면 **없는 파리티 결함**을 만들어 낸다(WAN-95 부류).
* 🚨 **백테만 있는 행은 `대상 아님`이다** — 같은 자로 재려면 **라이브의 존 대장**이 필요한데
  러너는 그것을 영속화하지 않는다(재파생 가능한 값이라 스냅샷에서 뺐다, WAN-306). 지어내지
  않는다(WAN-194).
* 🚨 **부류 (0)(키 없음)은 감사하지 않는다** — 재진입 행은 설계상 무키다(WAN-305). 안 빼면
  채택 규칙대로 한 재진입 매매가 「탐지 결함」으로 둔갑한다.
* 🚨 **동률·과반 미달이면 한 사유로 닫지 않는다** — argmax만 보고 결론 내기 금지(WAN-161 규약).
* 📌 **탭 시각 기준은 `focus_ms`라 상한이다** — 판정은 상위TF **봉 단위**로만 하고 초 단위
  비교를 하지 않는다.

## 5. 남은 것 — 서버 1회 실행이 §2 판정을 낸다

세션에 SSH가 없다(WAN-195/314/337/342와 같은 제약). 로컬 `live_limit_orders`는 **0행**이고
상위TF도 2026-08-14에서 멈춘다.

```bash
uv run alphablock stop-width --day 2026-08-17 --with-backtest --zone-audit --jobs 4
uv run alphablock stop-width --day 2026-08-18 --with-backtest --zone-audit --jobs 4
```

읽는 법:

* **`무효화 선행`이 과반** → §3의 문서화된 근사다. **크기를 기록하고 CLAUDE.md 문단으로
  닫는다**(수정 이슈 아님). 「무효화 봉 = 탭 봉」 건수를 함께 볼 것 — 그게 「한 봉」 서명이다.
* **`존 미탐지`가 과반** → 창으로 설명되지 않는 **엔진 파리티 결함**이다. 별도 이슈로 뺀다.
  (§2가 창 가설을 이미 기각했으므로 이 경우 원인은 창이 아니다.)
* **`창 밖`이 과반** → 대조 도구의 워밍업 근사다. `--warmup-days`를 늘려 재확인한다.
* **과반이 없으면** 한 사유로 닫지 말고 사유마다 따로 본다(도구가 그렇게 찍는다).

⚠️ 그 뒤 08-18 `10:04` **1건**이 같은 원인으로 설명되는지 확인한다 — 안 되면 그 1건만
재시작 계정이다(§1).

### 완료 기준 대조

| # | 기준 | 상태 |
| -- | -- | -- |
| 1 | §1 클러스터 대조 표 | ✅ §1(첫 코멘트 · 이 문서에 기록) |
| 2 | 원인 한 줄 판정 | ⏳ **부분** — 후보 둘(라이브 운영 이벤트 · 탐지 컨텍스트 창) 기각. 남은 갈래는 §5 서버 실행이 가른다 |
| 3 | 크기 | ✅ 08-17 **14/60 = 23.3%** · 08-18 **14/37 = 37.8%**(WAN-337 실측) |
| 4 | 수정 이슈 or CLAUDE.md 문단 | ⏳ §5 판정에 달렸다 — 이 문서와 CLAUDE.md 문단이 **자와 읽는 법**을 먼저 못 박는다 |
| 5 | 엔진·기본값·토대 불변 · 게이트 | ✅ |

🚨 **크기(23~38%)를 「파리티 대조가 그만큼 틀렸다」로 읽지 말 것** — 짝 없는 셋업은 손절폭
표에서 **빠지고**(WAN-333이 그렇게 고쳤다) 편향 점검 Δ가 08-17 0.000%p · 08-18 −0.014%p로
작다. **WAN-334의 손절폭 판정은 안 뒤집힌다.** 이 값이 재는 것은 「대조가 못 보는 셋업의
비중」이다.
