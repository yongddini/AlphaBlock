# WAN-477 — 수집기의 거래소 연결 셋이 시장 전체를 상시로 들고 있었다: USDⓈ-M만 받게 줄였다

> 운영 버그 수정 · 매매 규칙·기본값·토대 불변 · 실거래 보류 유지(`ALPHABLOCK_LIVE_TRADING=false`).

## 결론

WAN-476 결정문이 「미측정 · 미수정」으로 남긴 추정이 **맞았고 크기는 예상보다 컸다.** 수집기
(`data.collector.run_collector`)는 후보 풀 말고도 거래소 연결을 **셋** 만든다 — 기동 백필·갭 복구·펀딩·
꼬리 따라잡기(`exchange`) · 팔 수집(`_build_arm_collection`) · REST 이중 수집(`_build_rest_poller`).
ccxt는 연결마다 첫 `fetch_ohlcv` 때 `load_markets()`를 부르고 결과를 **인스턴스에** 들고 있는데, 셋이
**공유하지 않는다**(시장 dict도 그 안의 시장 객체도 연결마다 따로). 그래서 시장 4,708개(현물·USDⓈ-M·
COIN-M)가 **세 벌** 메모리에 있었다.

세 연결을 `data.exchange.create_collector_exchange()`(USDⓈ-M만 · 화폐 목록 안 받음 — WAN-476
`create_pool_exchange`와 같은 제한)로 바꿨다. 맥 실측으로 연결 셋의 RSS 증가가 **+390~412MB → +43~47MB**,
파이썬 힙이 **313.6MB → 32.1MB**다. 받는 봉·펀딩은 같다(아래 근거).

📌 **서버 숫자와 자릿수가 맞는다** — 서버 수집기의 평소 「RSS 59MB · RSS+스왑 564MB」(WAN-475 10-27)에서
기준 프로세스 몫(맥 약 190MB)을 빼면 약 370MB이고, 이 표의 「고치기 전」 연결 셋 +390~412MB와 같은
크기다. 그 대부분이 스왑에 있다가 09:02 같은 순간 다시 읽히는 몫이었을 가능성이 크다. ⚠️ 서버 실증은
PR 밖이다(아래).

## 측정표 (맥 M1 · 변형 × 자마다 새 프로세스 · 2026-10-29)

재현: `uv run python -m scripts.wan477_collector_conn_probe --all`(네트워크 필요 · 약 45초).
⚠️ **서버에서 돌리지 말 것** — 그 자체가 메모리 출렁임을 만든다(WAN-469 교훈).

### 메모리 — 연결 셋을 만들고 각자 첫 `fetch_ohlcv`(BTC 1분봉 2개)까지

| 변형 | 연결당 시장 | RSS 증가(추적 없음 · 2회) | 연결별 RSS 증가(추적 켬) | 파이썬 힙에 남은 몫 | 연결끼리 공유 |
| -- | --: | --: | -- | --: | -- |
| 연결 없음(기준) | — | 0.0MB | — | 0.0MB | — |
| **고치기 전** `create_exchange` × 3 | 4,708 | **+390.2 / +412.2MB** | 311.3 · 139.8 · 298.6MB | **313.6MB** | 안 함 |
| **고친 뒤** `create_collector_exchange` × 3 | 936 | **+46.9 / +42.9MB** | 30.1 · 26.5 · 21.0MB | **32.1MB** | 안 함 |

* 「추적 켬」 열은 `tracemalloc`이 RSS를 부풀린 값이라 연결별 비교용으로만 본다. 서버와 같은 조건의
  RSS는 「추적 없음」 열이다.
* 「공유 안 함」 = `a.markets is b.markets`도 `a.markets[심볼] is b.markets[심볼]`도 거짓. 그래서
  「연결을 하나로 합치기」 대안도 효과가 있지만(셋 → 하나), 스레드 공유 회피가 연결을 나눈 이유였다
  (`_build_arm_collection`·`_build_rest_poller` 독스트링). 제한을 거는 쪽이 같은 효과를 더 크게
  내면서(9분의 1) 그 설계를 안 건드린다 — 그래서 골랐다.

### GC 전체 수거(세대 2) — 같은 상태 · 추적 없음 · 5회 중앙값

| 변형 | 추적 중인 객체 | 세대 2 수거 | `gc.freeze()` 뒤 객체 | `gc.freeze()` 뒤 수거 |
| -- | --: | --: | --: | --: |
| 연결 없음(기준) | 191,859 | 35.7ms | 0 | 0.0ms |
| 고치기 전 | 370,922 | **151.0 / 152.7ms** | 0 | 0.0ms |
| 고친 뒤(가) | 229,753 | **53.3 / 54.4ms** | 0 | 0.0ms |

📌 (가) 연결 제한은 객체 **179k → 38k 추가**로, 전체 수거 시간을 약 3분의 1로 줄인다. (나) `gc.freeze()`는
기동 때까지의 객체를 수거 대상에서 아예 뺀다.

🚨 **이 표는 메모리에 다 올라와 있는 맥의 값이다.** 서버 가설(⚠️ 미측정)은 「객체가 스왑에 있으면 전체
수거가 그 페이지를 다 다시 읽고 그동안 GIL을 쥔다」인데, 그러면 서버의 수거 시간은 이 표가 아니라
**스왑에서 읽는 바이트 수**에 비례한다 — (가)가 그 바이트를 약 9분의 1로 줄인다. 가설을 가르는
측정은 아래 진단 로그다.

## 바꾼 것

* `data/exchange.py` — `restrict_to_usdm()`(WAN-476의 옵션 두 줄을 함수로 뽑음 · `create_pool_exchange`가
  그것을 부른다 · 동작 불변) · `create_collector_exchange()` 신설. `market_type="spot"`이면 제한을 안 건다
  (그 시장이 빠지므로). `create_exchange`는 **불변**(브로커·히스토리·수리 CLI 경로는 그대로).
* `data/collector.py` — 세 연결이 `create_collector_exchange`를 쓴다. 모듈이 `create_exchange`를 더는
  들여오지 않는다(새 경로가 옛 연결로 새지 않게 — 테스트가 고정).
* `data/gc_watch.py`(신설) + 설정 둘 — **둘 다 기본 꺼짐**:
  * `ALPHABLOCK_COLLECTOR_GC_LOG_MIN_MS` — 세대 2 수거가 이 ms 이상이면 WARNING 한 줄(`gc.callbacks`).
  * `ALPHABLOCK_COLLECTOR_GC_FREEZE_AFTER_START` — 기동 백필 뒤 `gc.freeze()`. 얼린 객체 중 순환 쓰레기는
    수거되지 않으므로 손잡이로만 둔다(켤지는 사용자 결정 · 진단 결과를 보고).
* `scripts/wan477_collector_conn_probe.py` — 위 측정표를 내는 도구.
* 테스트 5개 파일 — 가로채던 이름 `data.collector.create_exchange` → `create_collector_exchange`(이름만).

## 결과가 같다는 근거 (`tests/test_wan477_collector_exchange.py` · 네트워크 없음)

수집기가 거래소에 부르는 메서드는 `fetch_ohlcv` · `fetch_funding_rate` · `fetch_funding_rate_history`
셋과(`grep`으로 확인 · 그 밖에 `markets`·`currencies`를 읽는 자리 없음) 첫 호출의 `load_markets`뿐이고,
수집 심볼은 전부 USDⓈ-M 표기(`BTC/USDT:USDT`)다.

1. 새 연결의 시장 목록 요청은 USDⓈ-M 하나다(현물·COIN-M 0) · 키가 있어도 화폐 목록을 안 받는다.
2. 같은 고정 응답에서 세 메서드의 **결과와 보낸 요청 URL이** 옛 연결과 같다(봉 OHLCV · 현재 펀딩 ·
   펀딩 이력).
3. 팔 수집 · REST 이중 수집이 새 연결을 받는다(호출 인자로) · 기동 연결은 모듈에서 옛 함수가 사라진
   것으로 건다(기존 기동 테스트 5개가 새 이름을 가로채고 통과).
4. 현물 설정은 제한이 안 걸린다 · 옵션이 다른 인스턴스로 새지 않는다.
5. GC 훅: 설정 기본 꺼짐 · `None`이면 `gc.callbacks`를 안 건드린다 · 세대 0·1은 무시 · 문턱 이상만 로그 ·
   실제 `gc.collect()`에서 값이 채워진다 · `freeze_startup_objects`가 실제로 얼린다.

돌연변이 확인: `create_collector_exchange`에서 제한 한 줄을 빼면 1번 테스트 둘이 실패한다.
