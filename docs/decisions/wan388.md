# WAN-388 — 존을 뭉치로 보고 한 번만 들어가면 나은가 (존 병합 × 재탭 차단 2×2)

> 사용자 설계 2026-08-28: *「연쇄 손절 없이 하나의 병합된 존이면 손해가 덜하까 싶은거지」*
> → *「구성 존마다 재진입은 의미가 없을거같고 클러스터링 된거에서 재진입을 하는게 맞지」*

⚠️ **측정 전용이다.** `ConfluenceParams()`·`OrderBlockParams()`·`LeverageBookParams()`
기본값을 **하나도 안 바꿨다**(WAN-149 `combine_obs=False` · WAN-123 `retap_mode=
"every_tap"` 둘 다 불변). 채택은 **재-베이스라인 = 사용자 결정**이고 개발자 임의 착수
금지. 실거래 보류 유지(`ALPHABLOCK_LIVE_TRADING=false`).

## §0 엔진 — 두 축을 북 후보 생성에 배선했다 (옵트인, 안 주면 비트 동일)

`wan169_leverage_book.run_cells`/`_Task`에 축 둘이 생겼다. **새 스위치를 만들지
않았다** — 엔진에는 이미 둘 다 있었고(`OrderBlockParams.combine_obs` ·
`ConfluenceParams.retap_mode`) **북 후보 생성 경로에만 없었다**.

| 축 | 기본값 | 걸리는 층 |
| -- | -- | -- |
| `combine_obs` | `False`(채택) | **탐지** — `harness.detect_order_blocks(window, OrderBlockParams(combine_obs=…))` |
| `retap_mode` | `None`(= 채택 `"every_tap"`) | **시그널** — `harness.build_params(retap_mode=…)` |

- 기본값이면 `OrderBlockParams(combine_obs=False) == OrderBlockParams()`이고
  `build_params(retap_mode=None) == build_params()`라 **예전과 비트 단위로 같다**
  (테스트가 **값 동등성**으로 고정한다 — 이름이 아니라).
- 🚨 **`combine_obs`는 탐지 파라미터라 값마다 오더블록을 다시 탐지해야 한다**(WAN-149).
  그래서 네 팔이 payload를 **공유하지 않는다** — 공유하면 라벨만 다른 같은 숫자가 나온다.
- 🚨 **재탭 차단(`"once"`)과 재진입(WAN-273)은 다른 축이다.** 재탭은 *「무효화 전까지 그
  존을 다시 건드릴 때마다 새로 진입」*이고 재진입은 *「익절로 나온 뒤 재무장」*이다.
  `"once"`로도 재진입은 그대로 돈다 — 격자 네 팔 전부 재진입은 채택값(band)으로 켠 채다.
  회귀 테스트가 `entry_candidate_signals`가 **어느 시그널 목록을 소비하는지**로 고정한다
  (`signals` vs `retap_signals`).

**`PlacedSetup`에 라벨 둘**(`tap_index`·`zone_key`)을 후보에서 그대로 옮겼다 — 순수
라벨이라 배치·손익 어디에도 안 쓰이고 기본값이 후보 기본값과 같아 **비트 동일**이다
(`is_reentry`·`same_step_take_profit`·`trigger_time`과 같은 부류). 이게 없으면 「탭이 N%
준다」와 **「북 거래가 N% 준다」**를 북 층에서 가를 수 없다.

### 📌 그런데 값은 **거의 전부 재탭 차단**에서 온다 — 병합은 ≈0이다

**병합 단독이 두 상태 모두 노이즈선 안**이고(매탭 −0.0023 · 첫탭만 +0.0009), **상호작용도
≈0**이라 두 축은 **독립**이다. 즉 **병합은 빼도 헤드라인이 거의 그대로다**(팔 3 +0.0152 vs
팔 4 +0.0161, 차이 **+0.0009R** = 노이즈선의 5분의 1).

📌 **1등과 2등이 같은 점수에 다른 길로 도착한다** — 팔 3은 **gross를 올려서**(0.0765 →
0.0894 = +17%), 팔 4는 **비용을 줄여서**(0.1960 → 0.1829 = −7%). 병합이 gross를 깎는 대신
비용을 사는 교환이 **정확히 상쇄**된다.

### 🚨 이슈의 가설과 메커니즘이 다르다 — 기록

이슈는 *「병합이 손절폭을 넓혀 **비용**을 줄인다」*를 노렸는데, **재탭 차단이 값을 만든
경로는 비용이 아니라 gross다**(팔 3: 비용 −0.0024R뿐인데 gross +0.0129R). 재탭 차단은
손절폭을 안 건드리므로(0.724% → 0.734%) 당연하다. **재탭 거래가 첫탭 거래보다 나빴다**는
선별 효과이지 마찰 절감이 아니다.

📌 **병합의 폭 효과는 예상의 10분의 1이었다** — §1의 폭 배수 중앙값이 1.62~1.70배인데
거래 전체의 손절폭 중앙값은 **+9.3%**(0.724% → 0.791%)만 움직였다. **무는 탭이 18.7%뿐**
이라 중앙값이 거의 안 밀린다. 착수 전 환산(「1.7배면 −0.081R」)은 **무는 거래에 한정된
상한**이었고 전체로는 **−0.011R**이었다.

### 🚨 개선분에 채널이 하나 섞여 있다 — 이 표는 못 가른다

**재진입 거래가 1,591 → 4,142(팔 3) · 3,506(팔 4)로 2.2~2.6배가 됐다.** 재탭 후보가 슬롯을
안 잡으니 그 자리를 재진입이 채웠다(그래서 후보는 −57%인데 거래는 −12.7%만 준다). 개선분
중 **「재탭을 뺀 몫」과 「재진입이 늘어난 몫」을 이 격자는 분리하지 못한다** — WAN-323이
반익절 래더에서 겪은 「공유 자본이 자리를 비워 준다」 채널과 같은 부류다. **후속 이슈 감이다.**
