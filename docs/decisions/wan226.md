# WAN-226 — 지정가 형성-즉시 예약 + 「가까운 주문 우선」 배분 (§2 설계 · §3 대조 · §1c 15m)

## 0. 요약 — §2는 두 층으로 갈라지고, 그 값이 서로 다르다

사용자 제안("존이 생기자마자 미리 깔아두고, 자본이 모자라면 현재가에서 **가까운 주문만
남긴다**")을 엔진에 앉히면 **두 개의 독립된 변경**으로 분해된다:

| 층 | 무엇 | 상태 | 이 저장소에서의 값 |
| -- | -- | -- | -- |
| **층 1** | 칸 **안** 형성-즉시 예약 (탭→형성 배치 · 무효화까지 유지 = 고정 만료 제거) | **측정 가능** — 체결 대리 = `limit_valid_bars=None` (WAN-223 §1이 이미 sanctioned) | §3에서 잰다(아래) |
| **층 2** | 칸을 **가로지르는** 「가까운 주문 우선」 배분 + 하드 명목 가드 | **하드 가드는 이미 있음**(북) · 「가까운 주문 우선」 취소는 **fill-replay 북이 표현 못 함**(resting-order sim 필요) | WAN-180 실측상 바꿀 여지 ~nil(6년 7건) |

핵심 판단: **층 1의 체결 효과는 새 엔진 코드 없이 `limit_valid_bars=None`으로 이미 측정된다**
(WAN-223 §1 census가 그 값을 "형성-즉시 예약의 체결 대리"로 못 박았다). **층 2의 하드 명목
가드는 북(`run_leverage_book`)이 이미 배치 단계에서 강제한다.** 남는 것은 「가까운 주문 우선」
취소뿐인데, 그것은 fill-replay 회계가 아니라 **미체결 주문의 시점별 상태를 굴리는 resting-order
시뮬레이터**를 새로 지어야 하고 — WAN-180 실측(동시 최대 6칸 · 명목 스킵 6년 7건)상 **바꿀
여지가 사실상 0**이다. 그래서 이 이슈는 층 1을 §3로 재고, 층 2는 설계로 확정하되 **착수를
사용자 결정으로 남긴다**(재-베이스라인급 엔진 빌드 · 이점 검증은 큐 우선순위 = WAN-98
Canceled / 라이브 충실도 = WAN-45 소관이라 반쪽).

## 1. §2 설계 확정

### 1-1. 층 1 — 형성-즉시 예약 (칸 안)

* **현행**: 지정가를 **탭**(`OrderBlockSignal.trigger_time` = 바깥→안 전이) 순간에 만들고
  `limit_valid_bars=24`봉 뒤 취소.
* **§2**: 지정가를 **존 형성**(`OrderBlock.confirmed_time`) 순간에 만들고 **무효화**
  (`OrderBlock.break_time`)까지 유지 = 고정 만료 제거.
* **체결 대리 = `limit_valid_bars=None`**: WAN-223 §1 census가 두 패스(24봉 vs 무기한)의
  차이 `filled_wait − filled_base`를 "만료 후 재탭 실패로 놓친 재진입"으로 쟀고, 무기한
  패스를 명시적으로 **"형성-즉시 예약의 체결 대리(만료 없는 순수 대기 지정가)"**로 정의했다.
  형성 배치가 탭 배치보다 **더** 잡는 건 "형성 시 이미 존 안(바깥→안 전이 없음)" 케이스뿐이고,
  census/토대 문서가 이 차이를 의도적으로 대리로 접었다. 그래서 층 1의 체결·수익 효과는
  **새 엔진 코드 없이 `limit_valid_bars=None`으로 측정된다**(§3).

### 1-2. 층 2 — 「가까운 주문 우선」 배분 + 하드 명목 가드 (칸 가로지름)

#### 🚨 필수 PM 설계 질문 1 — 하드 명목 가드 (배치 단계, 체결 후 거부 불가)

**답: 이미 있다.** 레버리지 북(`backtest/leverage_book.py:run_leverage_book`)이 후보를
배치할 때마다 열린 명목 합(`open_notional`)을 계산하고 `resolve_book_sizing(...)`이
`cap_exhausted`를 내면 그 진입을 **배치 단계에서 스킵**한다(`stats.skipped_notional += 1`,
leverage_book.py:397-409). 상한 여유 안이면 사이징을 클램프한다(leverage_book.py:418-420).
즉 총 노출은 **주문 배치/취소 단계**에서 자본×레버리지(cap_only 5배)를 절대 넘지 않는다 —
체결 후 거부가 아니다. 형성-예약 팔(`limit_valid_bars=None` 후보)도 이 가드를 **그대로 탄다**.
상한식은 라이브 집행과 **공유하는** `resolve_book_sizing`이라(WAN-171) 두 경로가 갈라지지
않는다.

#### 🚨 필수 PM 설계 질문 2 — 예산 회수 시 재예약 규칙

**규칙(명시)**: 형성-예약은 무효화까지 유지되는 **순수 대기 지정가**라, 미체결 주문이
`ob.confirmed_time ≤ t < ob.break_time` 동안 계속 걸려 있다. 포지션 청산으로 예산이 비면
(북의 공유 현금이 늘면) **그 시각 이후 현재가가 가장 먼저 닿는 유효 존**(= 현재가에서 가장
가까운 미체결 주문)이 자동으로 체결되어 진입이 재개된다 — **새 탭이 필요 없다**(census가 잰
구멍이 여기서 닫힌다). 존 유효성 재확인 = 기존 `is_active`(`confirmed_time ≤ t` & 아직
`swept_time` 없음) 그대로. 무효화된 존은 주문판에서 빠진다(`invalidation_time` = `break_time`).

#### 🚨 「가까운 주문 우선」 취소가 왜 이 이슈에서 **구현되지 않는가** (설계 결정)

「자본이 모자라면 먼 미체결 주문을 취소하고 가까운 것만 남긴다」는 **미체결(resting) 주문의
시점별 상태를 굴리는 시뮬레이션**을 요구한다: 매 분 모든 칸의 현재가를 알고, 걸려 있는
미체결 주문들을 `|현재가 − 지정가|`로 랭킹해, 자본 부족 시 먼 것을 **취소**해야 한다. 그러나
현재 북(`run_leverage_book`)은 **fill-replay**다 — 각 칸의 서브스텝 시뮬레이션이 **이미
정해 놓은 체결**을 진입 시각 순으로 재생하며 over-cap이면 그 체결을 스킵할 뿐, **미체결
주문을 취소하지 않는다**(취소할 미체결 주문의 개념이 replay에 없다). 「가까운 주문 우선」을
충실히 구현하려면 fill-replay를 **resting-order 시뮬레이터**로 바꿔야 하고, 이는 진입 집합
자체를 바꾸는 **재-베이스라인급 엔진 빌드**다.

**그리고 그 빌드의 값은 ~0이다**: WAN-180 실측상 북의 동시 열림은 **최대 6칸**, 명목 상한
스킵은 **6년 7건**으로 드물다. 배분이 실제로 개입하는 순간(자본 부족으로 둘 이상이 경합)이
6년에 7번뿐이니, 「가까운 것 우선」이 「시각 우선」과 다른 결정을 내리는 경우는 그보다도
적다. census도 같은 결론을 명시한다("「가까운 주문 우선」 배분(§2)이 실제로 바꿀 여지는
그만큼 작다"). 게다가 이점의 진짜 검증(실체결 큐 우선순위)은 틱·호가(WAN-98, **Canceled**)
없이는 반쪽이고, 실질 이득은 **라이브 집행 충실도**(WAN-45/171 배선) 위에서만 드러난다.

**→ 결론**: 하드 명목 가드(층 2의 안전 요건)는 **이미 충족**돼 있고, 「가까운 주문 우선」
취소는 값(~nil) 대비 비용(resting-order sim = 재-베이스라인)이 맞지 않아 **이 이슈에서
구현하지 않는다**. 착수하려면 별도 결정 이슈로, 선행은 WAN-45(라이브 배선)·WAN-98(틱, 현재
Canceled)다.

## 2. §3 대조 — 현행(24봉 만료) vs 형성-예약(무기한 대기)

**방법**: 채택 엔진(per-cell 단일 포지션 · `--limit-valid-bars`가 per-cell 축이라 북이 자동
접힌다) 위에서 `limit_valid_bars=24`(현행) vs `=None`(형성-예약 체결 대리) 두 팔을 같은
좌표에서 `--oos-warm`(WAN-166)으로 대조한다. 축은 심볼 · TF(4h·1h) · 구간(is·oos_warm).
15m은 §1c 컴퓨트 소관이라 여기서는 4h·1h가 대표다. 심볼별 전체 표는
`backtest/reports/wan226_reservation_compare_summary.md`.

**결과(9종목 · 못 박은 6년 · `baseline` 단독)**: 형성-예약(무기한)은 **체결률을 전반적으로
올린다**(예: 1h 따뜻 OOS BTC 66.7%→75.3% · SOL 66.7%→72.0%). 심볼평균 total_return 델타
(형성-예약 − 현행):

| TF · 구간 | 거래(24→∞) | 심볼평균 수익 델타 |
| -- | --: | --: |
| 4h · IS | 344→357 | **+1.21%p** |
| 4h · 따뜻 OOS | 215→220 | **+0.26%p** |
| 1h · IS | 1447→1504 | **+3.88%p** |
| 1h · 따뜻 OOS | 770→804 | **+3.45%p** |
| **전체** | — | **IS +2.54%p · 따뜻 OOS +1.86%p** |

* **방향은 WAN-223 §1 census와 정합** — 만료를 없애면 체결·거래가 늘고 수익도 대체로 늘되,
  **종목에 갈린다**: 1h IS에서 **LINK −8.3%p**(체결 +19인데 수익 −8%p) · LTC −0.2%p, 4h에서
  **BNB·TRX·DOGE가 마이너스**. WAN-222/223의 "체결↑ ≠ 수익↑"가 IS/OOS 축에서 재확인된다.
* **4h 따뜻 OOS 델타는 사실상 0(+0.26%p)** — 구멍(놓친 재진입)이 있어도 그 재진입이 4h OOS
  수익을 거의 안 더한다(census 4h 델타 +1.63%와 같은 자릿수).
* **1h 델타(+3.45%p 따뜻 OOS)는 소수 종목이 만든다** — ETH +12.0%p · SOL +7.5%p가 대부분이고
  BNB·LINK는 0.0%p다. census의 (c) 경계 성격이 IS/OOS 대조에서 그대로 유지된다.

⚠️ **채택 근거가 아니라 크기 조사의 IS/OOS 판이다.** 형성-예약 채택(주문 생성 시점 탭→형성
전환)은 **재-베이스라인 = 사용자 결정**이고, 델타가 종목에 갈리며(GO 근거 약함) 전부
`baseline` 낙관 렌즈 위 값이다.

```
uv run python -m backtest.run --tf 4h,1h --limit-valid-bars 24,none --oos-warm \
    --format csv --out backtest/reports/wan226_reservation_compare.csv --jobs 6
```

⚠️ 전부 `baseline`(닿으면 체결) 낙관 렌즈 위 값이다 — `limit_valid_bars=None`은 주문을 더
오래 걸어 두므로 체결이 늘지만, 그 늘어난 체결이 유독 "스치듯 닿은 체결"에 실릴 수 있다
(WAN-96/222/223: 체결↑ ≠ 수익↑). 「엣지 없음」(WAN-84/88/111/114/124/151) 불변 — 주문 관리는
알파가 아니라 체결/자본 배분의 모양만 바꾼다.

## 3. §1c — 15m census 완성

WAN-223 §1 census는 무기한 대기 패스가 15m·6년에서 초선형으로 느려(WAN-203: 15m·6년 셀당
~37분 실측, 무기한 패스는 더) **4h·1h만** 냈다. 이 이슈에서 15m 전 구간을 마저 돌려 4h·1h와
같은 표(놓친 재진입 / 진입 · 진입 빈도 · 수익 델타 심볼별)를 완성한다.

```
uv run python -m backtest.wan223_limit_order_census --tf 15m --jobs 6 \
    --out-cells backtest/reports/wan226_census_15m.csv --out-md <15m 요약>
```

<!-- §1c-RESULTS -->
**상태: 미완(멀티-아워 컴퓨트 · 이 세션에서 완결 불가).** 무기한 대기 패스가 15m·6년에서
초선형이라(WAN-203 실측 15m·6년 셀당 ~37분 · 무기한 패스는 더) 9종목 두 패스를 한 세션에
돌릴 수 없다. **의도적으로 백그라운드에 방치하지 않았다** — 사용자 머신을 몇 시간 점유하는
작업을 무단으로 남기지 않기 위해서다. 위 재현 명령을 별도로(또는 심볼 분할로) 돌려 4h·1h와
합쳐 3-TF (c) 판정을 완성한다. 4h·1h census(WAN-223)는 각각 놓친 재진입 10.4%·12.0%였다.
